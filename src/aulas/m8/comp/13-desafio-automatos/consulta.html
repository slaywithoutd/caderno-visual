Resumo

Tudo no desafio gira em torno de três perguntas.

O Desafio 1 cobra autômatos finitos (AFD e AFN), autômatos com pilha, linguagens formais e análise léxica, em 60 minutos, sem consulta, com questões no papel e código corrigido por testes automáticos.

  • A lista de treino do professor tem três tipos de questão: dado o autômato, achar a linguagem; dada a linguagem, inventar o autômato; no AP, listar as computações de uma palavra.
  • Para achar a linguagem, dê a cada estado um nome que diga o que ele lembra da palavra lida e teste palavras curtas.
  • Para inventar um AFD, decida o que o estado precisa lembrar. Para um AP, decida o que a pilha guarda.
  • Na lista, o AP aceita só com estado final e pilha vazia ao mesmo tempo. No JFLAP e na aula 01 basta o estado final.
  • No código, quatro moldes resolvem quase tudo: AFD, AFN, AP e léxico. Código que não roda vale zero.
  • A área de treino no fim da página roda o seu autômato e o seu código em milhares de palavras e mostra onde errou.
  • AFD tem uma seta para cada símbolo em cada estado. As que faltam vão para um estado de erro, e ele precisa aparecer (ou ser dito).
  • Na tabela do AP, ε na coluna "topo da pilha" quer dizer "não desempilha". A transição vale com qualquer topo, inclusive com a pilha vazia.
  • "Termina em 1101": quando o símbolo não bate, a volta nem sempre é para o início. 11 seguido de 1 ainda termina em 11.
  • Linguagem que exige lembrar um n sem limite (aⁿbⁿ) não tem autômato finito. Se pediram AFD para ela, releia o enunciado.

Como é o desafio e como usar os 60 minutos

Individual, presencial, das 14h às 15h, sem nenhum tipo de consulta. Pode ter código, corrigido por testes automatizados, e questões de outra natureza (desenhar, descrever, justificar).

  • Código com erro de sintaxe ou que não roda recebe nota zero, mesmo que a ideia esteja certa.
  • Teste automatizado não lê intenção: o nome da função, a ordem dos parâmetros e o tipo do retorno precisam ser exatamente os pedidos.
  • O professor indicou a lista de treino com exercícios de AFD, AFN e AP. Todos estão resolvidos nesta página e no treino.

Dado o AFD em tabela: desenhar e achar a linguagem

Desenhe lendo a tabela linha por linha. Depois dê a cada estado um nome que diga o que ele lembra da palavra lida: a linguagem são as palavras que terminam num estado final.

  1. Linha da tabela = estado; coluna = símbolo; célula = destino. Marque o inicial com uma seta e os finais com círculo duplo. Símbolos com o mesmo destino viram uma seta só ("a, b").
  2. Procure o estado de erro (todas as setas voltam para ele e ele não é final) e estados que prendem a palavra.
  3. Nomeie os estados a partir do inicial: "q2 = palavras a⁺", "q3 = b⁺".
  4. Teste ε, cada símbolo sozinho e os pares. Anote quem é aceito.
  5. Escreva L e confira com duas palavras aceitas e duas rejeitadas.

Dado um AFD em tabela: desenhe o grafo de estados e determine a linguagem aceita (exercício 2 da lista).

  • A linguagem descreve todas as palavras aceitas e nenhuma outra. "Termina em c" erra o 2(a) por uma palavra só, a c.
  • Sempre confira ε: ela é aceita só se o inicial é final.
  • Quando a linguagem não tem padrão curto, descreva pelos estados com exemplos aceitos e rejeitados. É melhor que um padrão inventado.

Inventar um AFD: o que o estado precisa lembrar

Cada resposta possível vira um estado.

Antes de desenhar, responda: lendo da esquerda para a direita, o que preciso lembrar para decidir no fim? Cada resposta possível vira um estado, e cada símbolo diz como a resposta muda.

Exercício 5(d) da lista, termina em 1101. Os estados são q0 = ε, q1 = 1, q2 = 11, q3 = 110, q4 = 1101 (final). Avançar é seguir 1, 1, 0, 1; o cuidado está nas voltas (as setas de baixo na figura):

  • q2 (li 11) lendo 1: o lido termina em 111, e o maior começo de 1101 no fim é 11. Fica em q2.
  • q3 (li 110) lendo 0: 1100 não termina em nenhum começo de 1101. Volta para q0.
  • q4 (li 1101) lendo 1: 11011 termina em 11. Vai para q2, e não para q0.
  • q4 lendo 0: 11010 termina em 0. Volta para q0.

Duas operações que caem em pergunta de conceito:

  • Complemento: troque finais por não finais num AFD completo (com o estado de erro). Sai o AFD de Σ* − L.
  • Interseção e união: rode os dois AFDs juntos; o estado é o par (estado de um, estado do outro).

Invente AFDs para linguagens sobre {0, 1}: termina em 00, três 0 consecutivos, cada 0 entre dois 1, termina em 1101, palíndromos de comprimento 6 (exercício 5 da lista).

  • Complemento num AFD sem estado de erro sai errado: as palavras que morriam continuam rejeitadas.
  • Linguagem finita (palíndromos de comprimento 6 são 8 palavras) é sempre regular, mesmo que palíndromos em geral não sejam.
  • "Cada 0 entre dois 1" aceita ε e 111: não há 0 para quebrar a regra.

AFN em tabela: conjuntos de estados ativos

O AFN anda com um conjunto de estados.

Na tabela do AFN cada célula é um conjunto de estados, e ∅ quer dizer que aquele ramo morre. Para decidir uma palavra, acompanhe o conjunto de estados ativos símbolo a símbolo: aceita se no fim algum ativo é final.

  • Próximo conjunto = a união das células de todos os estados ativos, na coluna do símbolo lido.
  • Com transição vazia, acrescente sempre o ε-fecho: os estados que se alcançam só por ε, a partir de cada ativo.
  • Conjunto vazio no meio da palavra: todos os ramos morreram, a palavra é rejeitada.

Dado um AFN em tabela: desenhe o diagrama e descreva a linguagem aceita (exercício 1 da lista de AFN).

  • ∅ na tabela não é erro do enunciado: AFN não precisa de estado de erro.
  • Basta um ramo aceitar. Um ramo que morre não faz a palavra ser rejeitada.
  • Mudar só F muda a linguagem inteira: no 1(b), com F = {q1, q2, q3}, a linguagem vira a*, e ε entra porque q1 é final.

AFN para AFD: construção dos subconjuntos

A construção dos subconjuntos transforma um AFN num AFD equivalente: cada estado do AFD é um conjunto de estados ativos do AFN. Comece no ε-fecho de {q0}, calcule para onde cada símbolo leva o conjunto e crie só os conjuntos que aparecerem.

  • Um estado do AFD é final se o conjunto tem algum estado final do AFN.
  • O conjunto ∅ vira o estado de erro do AFD.
  • No pior caso aparecem 2ⁿ conjuntos, todos os elementos de 𝒫(Q). Na prática, poucos.
  • Por isso AFN e AFD reconhecem as mesmas linguagens: o não determinismo deixa o autômato menor, não mais poderoso.

  • Esquecer o ε-fecho, no começo e depois de cada símbolo.
  • Marcar como final só o conjunto que é exatamente F. Basta conter um final.

AP em tabela: como a lista escreve e quando aceita

A coluna "transições" junta destino e o que empilha.

Cada linha da tabela do AP diz: no estado q, lendo x da entrada com y no topo, vá para q' e empilhe z. Na lista, a palavra é aceita quando, lida toda, a máquina está num estado final e com a pilha vazia.

  • ε na coluna entrada: não lê nada. ε no topo: não desempilha, e a linha vale com qualquer topo. ε no que empilha: não empilha.
  • Topo a: a transição só vale com a no topo, e ela tira esse a.
  • É a mesma seta a, b → c da aula 01, escrita em tabela.
  • Duas linhas com o mesmo estado, entrada e topo (q1, a, ε na lista) são o não determinismo: a máquina segue as duas.

O AP do exercício 1 da lista: Σ = {a, b}, Γ = {a}, inicial q1, F = {q2}.

  • Em q1, cada símbolo lido empilha um a: a pilha conta quantos símbolos já passaram.
  • Um a pode ser "o do meio": vai para q2 sem empilhar.
  • Em q2, cada símbolo lido tira um a.
  • Pilha vazia no fim quer dizer que antes e depois do a do meio havia o mesmo número de símbolos.
  • L(M) = { uav : u, v ∈ {a,b}* e |u| = |v| }: comprimento ímpar com a no meio (pergunta 1(c)).

Na lista, o AP aceita com estado final e pilha vazia ao mesmo tempo. Ao responder, diga o critério que você usou.

  • Com o critério só de estado final, aa seria aceita (q1 → q1 → q2 com um a sobrando). A lista diz que aa ∉ L(M): o critério dela exige a pilha vazia.
  • "Topo ε" não testa se a pilha está vazia. Para isso existe o truque do $ no fundo.
  • Para converter um AP de "só final" para "final e vazia", acrescente um estado final novo que esvazia a pilha com transições ε.

Todas as computações de uma palavra no AP

Uma computação é uma sequência de configurações (estado, o que falta ler, pilha) ligadas por ⊢. Como o AP é não determinístico, liste todos os ramos: em cada passo, todas as linhas da tabela que se aplicam.

  • Nesta página a pilha é escrita com o topo à esquerda; ε é a pilha vazia. Na aula 01, o topo fica à direita. Diga qual convenção você usa.
  • Um ramo para quando nenhuma linha se aplica. Ele aceita só se parou com a entrada lida, num estado final e com a pilha vazia.
  • Para mostrar que w ∈ L, basta uma computação que aceita. Para mostrar que w ∉ L, mostre que todas param sem aceitar.

Qual é a classe da linguagem?

Regular se dá para decidir com memória limitada (só estados). Livre do contexto se basta uma pilha, que casa pares aninhados. Fora disso, nem AP resolve.

LinguagemClassePor quê, em uma linha
{aa, ab, ba, bb}, qualquer finitaregularum caminho por palavra
aⁿbᵐ (n, m ≥ 1), termina em 0, contém 101regulara memória não depende do tamanho
0ᵏ com k múltiplo de 2 ou de 3regularresto por 6
aⁿbⁿ, wwʳ, aⁿbᵐcⁿ⁺ᵐ, mesmo nº de 0 e 1livre do contexto, não regularuma contagem ou um espelho: a pilha resolve
aⁿbⁿcⁿ, ww, aᵖ com p primonem livre do contextoduas comparações ao mesmo tempo, ou sem padrão de repetição
  • Para dizer que é regular: mostre um AFD, AFN ou expressão regular.
  • Para dizer que não é regular: o argumento curto é "precisa lembrar n sem limite, e um AFD tem um número finito de estados" (casa dos pombos). A prova formal é o lema do bombeamento.
  • AFD, AFN e expressão regular reconhecem exatamente as linguagens regulares.
  • AP não determinístico reconhece exatamente as livres do contexto, as mesmas das GLC. O AP determinístico reconhece menos: wwʳ precisa do chute do meio.
  • Regulares ⊊ livres do contexto ⊊ sensíveis ao contexto ⊊ recursivamente enumeráveis (hierarquia de Chomsky).
  • Não achar AFD não prova nada. Não regular se prova com o lema (ou com o argumento da memória, se o enunciado aceitar).
  • Subconjunto de regular não é regular por isso: aⁿbⁿ está dentro de a*b*.
  • aⁿbᵐcᵏ com k = n + m é livre do contexto (uma pilha só), mas aⁿbⁿcⁿ não é.

Tokens à mão: maior casamento e prioridade

Pegue sempre o maior pedaço que casa com algum padrão.

Leia da esquerda para a direita. Em cada ponto, pegue o maior lexema que casa com algum padrão; se dois padrões casam o mesmo tamanho, vence o de maior prioridade (palavra-chave antes de identificador). Espaços e comentários são descartados.

  • Revise os termos na aula 07: lexema, padrão e token, erro léxico, diagramas de transição e maior casamento.
  • Cada padrão é uma linguagem regular: o léxico é um AFD por padrão, e é por isso que autômatos e léxico caem juntos.
  • Erro léxico só acontece quando nenhum padrão casa naquele ponto (@, # numa linguagem que não os usa).

Código sem consulta: os quatro moldes

Quatro funções em Python cobrem o que o tema permite pedir em código: aceitar com AFD, aceitar com AFN, aceitar com AP e quebrar um texto em tokens. Treine até escrever cada uma de cabeça, sem erro.

  • As versões com explicação linha a linha do AFD e do AFN estão na aula 01. Aqui ficam versões curtas, iguais às do treino.
  • A linguagem do desafio não foi informada. Os moldes estão em Python; a lógica é a mesma em qualquer linguagem.

1 · AFD. delta é um dicionário de dicionários; seta que falta conta como estado de erro.

def aceita_afd(delta, inicial, finais, w):
    estado = inicial
    for c in w:
        if c not in delta.get(estado, {}):   # sem seta: rejeita
            return False
        estado = delta[estado][c]
    return estado in finais

2 · AFN. Cada célula é um conjunto; '' é a transição vazia.

def fecho(delta, estados):
    pilha = list(estados)
    vistos = set(estados)
    while pilha:
        q = pilha.pop()
        for r in delta.get(q, {}).get('', set()):
            if r not in vistos:
                vistos.add(r)
                pilha.append(r)
    return vistos

def aceita_afn(delta, inicial, finais, w):
    ativos = fecho(delta, {inicial})
    for c in w:
        prox = set()
        for q in ativos:
            prox |= delta.get(q, {}).get(c, set())
        ativos = fecho(delta, prox)
    return len(ativos & set(finais)) > 0

3 · AP. Busca em largura nas configurações (estado, posição, pilha). A pilha é uma string com o topo no fim; aceita com estado final e pilha vazia.

from collections import deque

# trans: lista de (estado, le, topo, destino, empilha); '' = nada
def aceita_ap(trans, inicial, finais, w):
    inicio = (inicial, 0, '')
    fila = deque([inicio])
    vistos = {inicio}
    while fila:
        q, i, pilha = fila.popleft()
        if i == len(w) and q in finais and pilha == '':
            return True
        for (de, le, topo, para, poe) in trans:
            if de != q:
                continue
            if le != '' and (i >= len(w) or w[i] != le):
                continue
            if topo != '' and (pilha == '' or pilha[-1] != topo):
                continue
            nova = pilha[:-1] if topo != '' else pilha
            nova = nova + poe[::-1]          # o 1º símbolo de poe fica no topo
            if len(nova) > 2 * len(w) + 5:   # corta ramos que só empilham
                continue
            conf = (para, i + (1 if le != '' else 0), nova)
            if conf not in vistos:
                vistos.add(conf)
                fila.append(conf)
    return False

4 · Léxico à mão, com maior casamento e palavra-chave depois do identificador inteiro.

PALAVRAS = {'se': 'SE', 'senao': 'SENAO', 'enquanto': 'ENQUANTO'}
DUPLOS = {'==': 'IGUAL', '!=': 'DIF', '<=': 'MENOR_IG', '>=': 'MAIOR_IG'}
SIMPLES = {'=': 'ATRIB', '<': 'MENOR', '>': 'MAIOR', '+': 'MAIS', '-': 'MENOS',
           '*': 'VEZES', '/': 'DIV', '(': 'ABRE', ')': 'FECHA', ';': 'PV'}

def tokens(codigo):
    saida = []
    i = 0
    while i < len(codigo):
        c = codigo[i]
        if c in ' \t\n':
            i += 1
        elif c.isalpha() or c == '_':
            j = i
            while j < len(codigo) and (codigo[j].isalnum() or codigo[j] == '_'):
                j += 1
            lex = codigo[i:j]
            saida.append((PALAVRAS.get(lex, 'ID'), lex))
            i = j
        elif c.isdigit():
            j = i
            while j < len(codigo) and codigo[j].isdigit():
                j += 1
            saida.append(('NUM', codigo[i:j]))
            i = j
        elif codigo[i:i + 2] in DUPLOS:        # dois caracteres antes de um
            saida.append((DUPLOS[codigo[i:i + 2]], codigo[i:i + 2]))
            i += 2
        elif c in SIMPLES:
            saida.append((SIMPLES[c], c))
            i += 1
        else:
            raise ValueError(f'erro léxico: {c!r} na posição {i}')
    return saida

  • No AP, sem o corte de tamanho (ou o conjunto vistos), uma linha ε, ε → a roda para sempre.
  • No AFN, delta[q][c] sem .get quebra com KeyError na primeira célula ∅.
  • Laço while do léxico sem avançar i num dos ramos: o programa trava e o teste estoura o tempo.
