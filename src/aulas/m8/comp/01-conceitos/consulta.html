Conjuntos: pertence, subconjunto, vazio, união e interseção

Um conjunto é uma coleção de coisas, sem ordem e sem repetição, escrita entre chaves. {a, b} é o mesmo que {b, a}.

  • x ∈ A: x pertence a A, é um dos elementos de A. x ∉ A: não pertence.
  • B ⊆ A: B é subconjunto de A, tudo que está em B também está em A. B ⊊ A (inclusão própria): subconjunto, e A tem algo a mais.
  • ∅ ou { }: o conjunto vazio, sem nenhum elemento.
  • A ∪ B (união): o que está em A ou em B. A ∩ B (interseção): o que está nos dois. A − B (diferença): o que está em A e não em B.
  • Finito: dá para listar tudo. Infinito: a lista nunca acaba, como os números naturais.

Descrever um conjunto por uma regra: { x | condição }

Conjunto infinito não dá para listar. Você escreve { x | condição } e lê "o conjunto dos x tais que a condição vale".

{ aⁿbⁿ | n ≥ 0 } = { ε, ab, aabb, aaabbb, … }
  • Leia: "as palavras formadas por n letras a seguidas de n letras b, para todo n a partir de 0".
  • n ≥ 0 diz quais valores n pode assumir.
  • Ler aⁿ como potência de número. Aqui ele quer dizer a letra a repetida n vezes: a³ = aaa.

Como ler os símbolos que vão aparecer

A tabela traduz cada símbolo da aula para palavras, com um exemplo.

  • Convenção dos livros: letras do começo do alfabeto (a, b, c) são símbolos; letras do fim (u, v, w, x, y, z) são palavras; maiúsculas (S, A, B) são variáveis de gramática.

Produto cartesiano e conjunto das partes 𝒫(A)

O conjunto das partes 𝒫(A), ou conjunto potência, junta todos os jeitos de escolher elementos de A: cada escolha é um subconjunto, incluindo escolher nenhum e escolher todos. O produto cartesiano (×) forma todos os pares possíveis: Q × Σ é o conjunto dos pares (estado, símbolo).

𝒫(A) = { B | B ⊆ A } · |𝒫(A)| = 2^|A|
  • |A|, com as barras, é a cardinalidade de A: quantos elementos ele tem.
  • 2^|A| porque cada elemento tem duas opções: entra ou não entra.
  • A = {1, 2, 3}: 𝒫(A) = {∅, {1}, {2}, {3}, {1,2}, {1,3}, {2,3}, {1,2,3}}, 2³ = 8 elementos. Os elementos de 𝒫(A) são conjuntos.
  • Q × Σ é o que a função de transição do AFD recebe.
  • Uma função que devolve um elemento de 𝒫(Q) devolve um conjunto de estados. É assim que a matemática escreve "pode ir para vários lugares ao mesmo tempo" (ou para nenhum, com ∅), como no AFN e no AP.

Símbolo, alfabeto e palavra

Alfabeto (Σ) é um conjunto finito de símbolos. Palavra é uma sequência finita de símbolos do alfabeto, um do lado do outro.

  • Símbolo: qualquer marca que dá para distinguir de outra, como a, 0, +. A teoria não define símbolo além disso.
  • O alfabeto precisa ser finito. Ex.: Σ = {a, b} ou Σ = {0, 1}.
  • Palavra também se chama cadeia ou sentença. A ordem importa: ab ≠ ba.
  • Palavra vazia (ε): a sequência com zero símbolos, como a string "" em programação. Alguns livros escrevem λ.
  • Comprimento |w|: quantos símbolos a palavra tem.
  • abba é uma palavra sobre {a, b}. |abba| = 4, |ε| = 0.

Σ* e Σ⁺: todas as palavras de um alfabeto

Σ* ("sigma estrela") é o conjunto de todas as palavras possíveis sobre Σ, de qualquer tamanho, incluindo ε. Σ⁺ ("sigma mais") é o mesmo, sem a palavra vazia.

Σ* = Σ⁰ ∪ Σ¹ ∪ Σ² ∪ Σ³ ∪ … · Σ⁺ = Σ* − {ε}
  • Σⁿ: as palavras de comprimento n. Σ⁰ = { ε }.
  • Σ = {a, b}: Σ¹ = {a, b}; Σ² = {aa, ab, ba, bb}, 2² = 4 palavras; Σ³ tem 2³ = 8.
  • Com |Σ| = k há kⁿ palavras de comprimento n.
  • Achar que Σ* contém palavras infinitas. Σ* é infinito (se Σ tiver pelo menos um símbolo), mas cada palavra dentro dele é finita.

Linguagem formal

Uma linguagem é uma escolha de palavras: as que você considera válidas, e as outras ficam de fora. Formalmente, uma linguagem L sobre Σ é qualquer subconjunto de Σ*, finito, infinito ou vazio.

  • A matéria inteira trata de uma pergunta: quais sequências de símbolos são válidas? Um compilador faz isso com programas; um validador de e-mail, com endereços.
  • Σ* e Σ⁺ também são linguagens sobre Σ.
  • Uma linguagem de programação é o conjunto de todos os programas válidos. Cada programa é uma palavra (bem longa) sobre o alfabeto dos caracteres do teclado.
L ⊆ Σ*
  • Σ = {a, b}: "as palavras que começam com a" é uma linguagem, {a, aa, ab, aaa, …}.

∅ ≠ {ε}: ∅ não tem nenhuma palavra; {ε} tem exatamente uma, a vazia. As duas são linguagens.

Prefixo, sufixo e subpalavra

Prefixo é um pedaço do começo da palavra; sufixo, um pedaço do fim. Subpalavra é qualquer pedaço contínuo de dentro dela, sem pular letras.

  • Toda palavra é prefixo, sufixo e subpalavra de si mesma, e ε também é as três coisas.
y é subpalavra de w se existem palavras x e z com w = xyz
  • Prefixo é o caso em que x = ε; sufixo, quando z = ε.
  • Por isso o livro diz "subpalavra é qualquer prefixo de um sufixo": corte um fim e depois um começo, sobra um pedaço do meio.
  • Prefixos de abb: ε, a, ab, abb. Sufixos de abb: ε, b, bb, abb.
  • bb é subpalavra de abba; aa não é (teria que pular os b).

Concatenação, concatenação sucessiva e reverso

Concatenar vw (às vezes v·w) é escrever v e logo depois w. É o + de strings em programação.

  • Associativa: tanto faz por onde você começa a juntar.
  • ε é o elemento neutro: juntar com nada não muda nada.
  • Não é comutativa: trocar a ordem muda o resultado.
  • Concatenação sucessiva wⁿ: w repetida n vezes. Por definição, w⁰ = ε (repetir zero vezes dá a palavra vazia).
  • Reverso wᴿ: a palavra de trás para frente. Um palíndromo é uma palavra igual ao próprio reverso.
εw = wε = w · |vw| = |v| + |w| · w⁰ = ε
  • v = ab e w = ba: vw = abba.
  • (ab·c)·d = ab·(c·d) = abcd.
  • ab·ba = abba, mas ba·ab = baab.
  • (ab)³ = ababab.
  • w = abc: wᴿ = cba. abba é palíndromo.

Operações sobre linguagens: concatenação e fecho de Kleene

Linguagens são conjuntos de palavras, então valem as operações de conjuntos. Há mais duas próprias: a concatenação de linguagens e o fecho de Kleene.

  • L₁ ∪ L₂: palavras que estão em uma ou na outra. L₁ ∩ L₂: nas duas. L₁ − L₂: na primeira e não na segunda.
  • Concatenação L₁L₂: todas as combinações "uma palavra de L₁ seguida de uma de L₂".
  • Fecho de Kleene L*: juntar palavras de L quantas vezes quiser, inclusive nenhuma. É o mesmo "*" de Σ*.
L₁L₂ = { uv | u ∈ L₁ e v ∈ L₂ } · L* = L⁰ ∪ L¹ ∪ L² ∪ …, com L⁰ = {ε}
  • {a, b}·{c} = {ac, bc}.
  • L = {ab}: L* = {ε, ab, abab, …}.

Gramática: regras que geram palavras

Uma gramática é uma receita de substituições: você começa com um símbolo especial e vai trocando pedaços pelas regras até sobrar só letras "de verdade". É a descrição finita que produz todas as palavras de uma linguagem infinita, e nenhuma outra.

  • V: as variáveis (ou não-terminais), símbolos de rascunho que ainda vão ser trocados. Escritas em maiúscula: S, N, D, E.
  • T: os terminais, os símbolos que aparecem na palavra final (o alfabeto da linguagem). V e T não têm símbolo em comum.
  • P: as regras de produção, escritas α → β e lidas "α pode ser trocado por β". α e β são sequências de variáveis e terminais; α tem pelo menos uma variável.
  • S: a variável inicial, de onde tudo começa (S ∈ V).
G = (V, T, P, S)
  • Uma quádrupla. S → aSb | ε abrevia duas regras, S → aSb e S → ε: a barra | se lê "ou".

Derivação (⇒), forma sentencial e derivação mais à esquerda

Um passo de derivação (⇒) aplica uma regra uma vez. O que está em volta fica igual; só o pedaço α é trocado.

  • Forma sentencial: qualquer sequência que aparece no meio do caminho, misturando variáveis e terminais, como aaSbb.
  • Derivação mais à esquerda: em cada passo, troca-se a variável mais à esquerda. É só uma convenção para todos fazerem na mesma ordem.
se α → β é uma regra, então uαv ⇒ uβv
  • ⇒*: zero ou mais passos. ⇒⁺: um ou mais passos.
  • Com a regra S → aSb: aSb ⇒ aaSbb (trocamos o S do meio).
  • Na figura, a cada passo a variável mais à esquerda é trocada e a árvore cresce embaixo.

Linguagem gerada L(G) e gramáticas equivalentes

A linguagem de uma gramática é o conjunto de todas as palavras que dá para fabricar com ela, começando em S e parando quando só sobram terminais. O livro escreve GERA(G) ou L(G).

  • Duas gramáticas são equivalentes se geram a mesma linguagem, L(G₁) = L(G₂), mesmo com regras diferentes.
L(G) = { w ∈ T* | S ⇒⁺ w }
  • Leia: "as palavras w feitas só de terminais tais que, partindo de S, chega-se em w em um ou mais passos".
  • Exemplo do livro, duplo balanceamento: G = ({S}, {a,b}, {S → aSb, S → ε}, S) gera { aⁿbⁿ | n ≥ 0 } = {ε, ab, aabb, aaabbb, …}. Por que a quantidade de a e b sai igual: ver livres do contexto.
  • Exemplo do livro, números naturais: N → D | DN e D → 0 | 1 | … | 9 geram qualquer sequência de dígitos. N é "um número" e D é "um dígito".

Gerar × reconhecer: formalismos e autômatos

Um formalismo é um jeito preciso, com regras fixas, de descrever uma linguagem. Um formalismo gerador fabrica as palavras; um reconhecedor recebe uma palavra e responde "sim, pertence" ou "não pertence".

  • A gramática é um formalismo gerador.
  • Um autômato, uma máquina abstrata, é um formalismo reconhecedor.
  • A matéria toda gira em torno de qual gramática corresponde a qual máquina. O mapa completo é a Hierarquia de Chomsky.

Autômato finito: uma máquina de estados

Um autômato finito é um modelo de computador bem simplificado. A única memória dele é saber em qual estado está, e o número de estados é fixo.

  • Exemplo da aula: o controlador de uma porta automática. Estados: Aberto e Fechado. Entradas: ninguém nos tapetes, alguém na frente, alguém atrás, alguém nos dois.
  • Para cada par (estado, entrada) há uma regra: fechada e alguém chega, ela abre; aberta e ninguém nos tapetes, ela fecha; nos outros casos, continua aberta.
  • Essa tabela de regras é a função de transição, escrita com a letra grega δ (delta).
  • A entrada vem escrita numa fita dividida em células, um símbolo por célula. A máquina lê da esquerda para a direita, uma célula por vez, sem voltar.
  • Elevadores e máquinas de refrigerante funcionam assim. Na computação, autômatos finitos estão nas expressões regulares e na análise léxica.
δ(Fechado, Frente) = Aberto

AFD: como o autômato finito determinístico lê uma palavra

Um AFD (autômato finito determinístico) é descrito por cinco coisas: os estados, as letras que ele lê, a tabela de regras, onde começa e onde aceita. Determinístico quer dizer que nunca há dúvida: em cada estado, para cada letra, existe exatamente uma seta.

  • No desenho, cada estado é um círculo. O estado inicial (só existe um) tem uma seta solta apontando para ele. Os estados finais, ou de aceitação, têm círculo duplo e podem ser vários. Os outros são chamados de intermediários.
  • Cada transição é uma seta com uma letra: "estando em q, se ler x, vá para r".
  • A palavra é aceita quando duas coisas valem ao mesmo tempo: todos os símbolos foram lidos e a máquina parou num estado final. Caso contrário, é rejeitada.
M = (Q, Σ, δ, q₀, F) com δ: Q × Σ → Q
  • Uma 5-upla. Q: o conjunto finito de estados. Σ: o alfabeto. δ: a função de transição. q₀ ∈ Q: o estado inicial. F ⊆ Q: o conjunto de estados finais.
  • δ: Q × Σ → Q se lê "δ recebe um estado e um símbolo e devolve um estado". Q × Σ é um produto cartesiano.
  • δ(q0, a) = q1: em q0, lendo a, vá para q1.

AFD: M = (Q, Σ, δ, q₀, F) com δ: Q × Σ → Q. Exatamente uma seta por estado e por símbolo. Aceita se leu tudo e parou num estado final.

Estado de erro (trap state)

No AFD toda seta precisa existir, então a palavra que já não tem salvação vai para um estado de erro (trap state, ou estado armadilha). Ele não é final e todas as setas que saem dele voltam para ele.

  • Quem entra não sai, e a palavra é rejeitada.
  • No desenho, é comum omitir o estado de erro e as setas que levam a ele, para não poluir. Fica combinado: seta que falta vai para o erro.
  • O AFN não precisa dele: ali uma seta pode faltar de verdade.

L = { aⁿbᵐ | n ≥ 1 e m ≥ 1 }: um a depois dos b leva para q3, o erro. Na tabela, linha é o estado atual, coluna é o que foi lido, a casa é para onde vai.

  • → marca o estado inicial e * marca os finais.
  • No AFD, cada casa tem exatamente um estado, e q3 recebe tudo o que "deu errado".
  • No AFN, cada casa tem um conjunto de estados. ∅ quer dizer "não há seta": o caminho morre ali, sem precisar de q3.

Estado de erro (trap state): não é final e todas as setas dele voltam para ele. O AFD precisa dele para completar a tabela; o AFN não precisa.

AFN: quando a máquina tem escolha

Num AFN (autômato finito não determinístico, também chamado de AFND), a partir de um estado e de uma letra a máquina pode ir para mais de um estado, ou para nenhum. Ele também pode ter ε-transições, setas que mudam de estado sem ler nada da fita.

  • São essas duas coisas que separam o determinístico do não determinístico.
  • São as mesmas cinco peças do AFD. Só a tabela de regras muda: cada casa guarda um conjunto de destinos (que pode ser vazio, e aí o caminho só acaba), e aparece uma coluna extra para ε.
M = (Q, Σ, δ, q₀, F) com δ: Q × Σ_ε → 𝒫(Q), onde Σ_ε = Σ ∪ {ε}
  • Compare com o AFD, δ: Q × Σ → Q. Trocar Σ por Σ_ε libera as ε-transições ("ler" ε é não ler nada).
  • Trocar Q por 𝒫(Q) faz a resposta ser um conjunto: {q1, q2} para duas opções, ∅ para nenhuma.

AFD × AFN: no AFN, δ: Q × Σ_ε → 𝒫(Q). Vários destinos (ou nenhum) para o mesmo símbolo, e ε-transições. O AFN não precisa de estado de erro.

Computação não determinística: ramos e estados ativos

A execução de um AFN é uma árvore de possibilidades: a raiz é o início, e cada ponto onde há escolha abre ramos. A palavra é aceita se pelo menos um ramo lê tudo e para num estado final.

  • Ramos sem seta para seguir morrem.
  • Jeito prático de acompanhar sem desenhar a árvore: anote, a cada letra, o conjunto de estados em que algum ramo está. É o que a figura faz.

Exemplo 2 da aula: o AFN sobre {0, 1} que reconhece as palavras com 11 ou 101 como subpalavra (subcadeia), lendo 010110.

  • δ(q1, 1) = {q1, q2} é a escolha: ficar ou apostar que o padrão começou.
  • δ(q2, ε) = {q3} é a ε-transição: pula o 0 do meio de 101 e transforma o padrão em 11.

Linguagens regulares: AFD, AFN e regex têm o mesmo poder

Uma linguagem é regular quando dá para construir um AFD que aceita exatamente as palavras dela. AFN, AFN-ε (AFN com ε-transições), expressão regular e gramática regular descrevem exatamente a mesma classe.

  • Toda linguagem finita é regular: com um número finito de palavras, dá para montar um caminho de estados para cada uma. Exemplo da aula: {aa, ab, ba, bb}.
  • Toda linguagem regular pode ser escrita de dois jeitos: com um AFD, que reconhece, ou com uma expressão regular (regex), que descreve. a*b* quer dizer "zero ou mais a, depois zero ou mais b"; o * é "repita quantas vezes quiser, inclusive nenhuma".
  • Gramática regular: regras só do tipo A → aB ou A → a (linear à direita). Gera exatamente as linguagens regulares, o Tipo 3.
  • Para todo AFN existe um AFD que reconhece a mesma linguagem, e todo AFD já é um AFN (um que nunca tem escolha). A vantagem do AFN é ser menor e mais fácil de desenhar.
  • Com linguagens infinitas, algumas são regulares e outras não, porque a memória do AFD é limitada: ver linguagens não-regulares.
L é regular ⇔ existe um AFD M com L(M) = L
  • L(M) se lê "a linguagem de M": o conjunto das palavras que M aceita.
  • AFN → AFD: os estados do AFD são os conjuntos de estados ativos, como os da figura do AFN. Por isso o AFD pode precisar de até 2^|Q| estados, um para cada elemento de 𝒫(Q).

Regular ⇔ existe AFD ⇔ existe AFN ⇔ existe expressão regular. Toda linguagem finita é regular.

Para todo AFN existe um AFD equivalente: os dois reconhecem exatamente as linguagens regulares. Com pilha isso muda (seção 8).

  • A frase certa é "toda linguagem regular pode ser expressa por um AFD ou por uma regex". Com "toda linguagem formal" ela fica falsa: aⁿbⁿ é uma linguagem formal e não tem AFD nem regex.

Simulando AFD e AFN em Python

No AFD, a tabela δ vira um dicionário de dicionários e o loop segue uma seta por letra. No AFN, a versão em largura guarda o conjunto de estados ativos.

  • Para o AFN, a aula listou três ideias. Rodar uma cópia do autômato por ramo, em paralelo (threads), o que exige sincronizar os processos.
  • Percorrer a árvore em largura: todos os ramos avançam uma letra por vez, como na figura do AFN.
  • Ou em profundidade, com backtracking: segue um ramo até o fim e, se falhar, volta ao último ponto de escolha e tenta outro.

AFD de aⁿbᵐ, com q3 como estado de erro (o simulador que o professor mostrou):

def afd(delta, q0, F, cadeia):
    estado = q0                      # começa no estado inicial
    for c in cadeia:                 # lê um símbolo por vez
        estado = delta[estado][c]    # segue a única seta possível
    return estado in F               # aceita se parou num estado final

delta = {                            # aⁿbᵐ, n, m ≥ 1 (q3 é o erro)
    'q0': {'a': 'q1', 'b': 'q3'},
    'q1': {'a': 'q1', 'b': 'q2'},
    'q2': {'a': 'q3', 'b': 'q2'},
    'q3': {'a': 'q3', 'b': 'q3'}}
print(afd(delta, 'q0', ['q2'], 'aaabbbb'))   # True

AFN "contém 11 ou 101", em largura, em poucas linhas:

def fecho(delta, estados):           # acrescenta quem se alcança por ε
    pilha, vistos = list(estados), set(estados)
    while pilha:
        q = pilha.pop()
        for r in delta.get(q, {}).get('ε', set()):
            if r not in vistos:
                vistos.add(r)
                pilha.append(r)
    return vistos

def afn(delta, q0, F, cadeia):
    ativos = fecho(delta, {q0})
    for c in cadeia:
        proximos = set()
        for q in ativos:
            proximos |= delta.get(q, {}).get(c, set())   # sem seta: ramo morre
        ativos = fecho(delta, proximos)
    return any(q in F for q in ativos)   # algum ramo parou num estado final?

delta = {                            # contém 11 ou 101
    'q1': {'0': {'q1'}, '1': {'q1', 'q2'}},
    'q2': {'0': {'q3'}, 'ε': {'q3'}},
    'q3': {'1': {'q4'}},
    'q4': {'0': {'q4'}, '1': {'q4'}}}
print(afn(delta, 'q1', ['q4'], '010110'))    # True

Linguagens não-regulares: o limite do autômato finito

Uma linguagem é não-regular quando nenhum autômato finito a reconhece. Em geral ela exige contar sem limite ou casar pares, e a memória do autômato finito não dá conta.

  • Um AFD com 5 estados consegue distinguir no máximo 5 "situações".
  • Para reconhecer aⁿbⁿ, ele precisaria lembrar quantos a leu, para depois conferir os b. Esse número pode ser 6, 100, um bilhão… não cabe numa quantidade fixa de estados.
  • Se nem aⁿbⁿ cabe num autômato finito, é preciso algo mais forte: as gramáticas livres do contexto (para gerar) e os autômatos com pilha (para reconhecer).

Exemplos clássicos:

  • { aⁿbⁿ | n ≥ 0 }: a mesma quantidade de a e b, com os a antes. No vídeo aparece como 0ⁿ1ⁿ, a mesma linguagem com outros símbolos.
  • { wwᴿ | w ∈ {a,b}* }: uma palavra seguida do seu reverso, ou seja, palíndromos de tamanho par (abba, aa).
  • Parênteses balanceados: (()(())). Cada ( precisa de um ) depois.
  • { w | w tem o mesmo número de a e b }, em qualquer ordem.
  • { aᵖ | p é primo } e { ww | w ∈ {a,b}* } (uma palavra repetida duas vezes, como abab).
  • "Tem que contar" precisa ser contagem ilimitada que será comparada depois. As cadeias binárias com o mesmo número de ocorrências de 01 e de 10 parecem exigir contagem, mas formam uma linguagem regular: essas ocorrências se alternam, então basta saber o primeiro e o último símbolo. Um AFD faz isso com poucos estados.

Lema do bombeamento

Em toda linguagem regular, qualquer palavra comprida o bastante tem, perto do começo, um pedaço que você pode repetir quantas vezes quiser (ou apagar), e a palavra continua na linguagem.

  • Intuição não é prova; o lema é a ferramenta para provar.
  • Ele vem do princípio da casa dos pombos: se 4 pombos entram em 3 casas, alguma casa fica com 2.
  • No autômato, os pombos são os passos de leitura e as casas são os estados. Se a palavra é maior do que o número de estados, algum estado é visitado duas vezes.
  • O trecho lido entre as duas visitas ao mesmo estado é um laço, que dá para repetir.
  • Pense em p, o comprimento de bombeamento, como o número de estados do AFD: palavras com p letras ou mais obrigatoriamente passam por um laço.
Se L é regular, existe p tal que toda w ∈ L com |w| ≥ p pode ser dividida em w = xyz com
|y| ≥ 1 · |xy| ≤ p · xyⁱz ∈ L para todo i ≥ 0
  • |y| ≥ 1: o pedaço repetível tem pelo menos uma letra.
  • |xy| ≤ p: ele está entre as p primeiras letras.
  • xyⁱz ∈ L: repetir y i vezes (ou apagar, com i = 0) mantém a palavra em L. xy²z = xyyz.

Para que serve o lema: provar que L não é regular

O lema diz "se é regular, então é bombeável". Ele serve pelo caminho inverso, a contrapositiva: "se não é bombeável, não é regular".

  • A prova é por contradição: você supõe que L é regular, aplica o lema e chega numa coisa impossível. Logo a suposição era falsa.
  • Contrapositiva é a mesma lógica de "se choveu, a rua está molhada; a rua está seca, então não choveu".
  • Pense num jogo contra um adversário que defende que L é regular. Onde o lema diz "existe", quem escolhe é ele; onde diz "para todo", você precisa ganhar em qualquer caso.

Receita, jogando com aⁿbⁿ:

  • 1. O adversário escolhe p. Você não sabe o valor, então trata p como um número qualquer.
  • 2. Você escolhe uma palavra w ∈ L com |w| ≥ p, uma que deixe o adversário sem saída. Para aⁿbⁿ: w = aᵖbᵖ (p letras a seguidas de p letras b).
  • 3. O adversário divide w = xyz respeitando |y| ≥ 1 e |xy| ≤ p. Você precisa considerar todas as divisões possíveis.
  • 4. Você escolhe um i e mostra que xyⁱz ∉ L.
  • Como funcionou para toda divisão, L não satisfaz o lema. Contradição: L não é regular.

Na figura, mexa em p, tente esconder y onde quiser e veja se escapa.

O lema do bombeamento só prova que uma linguagem não é regular. Para aⁿbⁿ: escolha w = aᵖbᵖ; como |xy| ≤ p, y só tem a, e xy²z sai de L.

  • Escolher um p específico ("seja p = 3"). Quem escolhe p é o adversário.
  • Escolher você mesmo a divisão xyz. Você tem que derrotar todas.
  • Escolher w curta demais ou fora de L.
  • Achar que "passar no lema" prova que L é regular. Existem linguagens não-regulares que passam.

Linguagens livres do contexto e GLC

Uma gramática livre do contexto (GLC) é uma gramática em que toda regra troca uma única variável por alguma coisa. Uma linguagem livre do contexto (LLC) é a gerada por alguma GLC.

  • As LLC são uma classe maior que a das regulares: toda linguagem regular é LLC, e algumas LLC (como aⁿbⁿ) não são regulares.
  • O exemplo típico é o duplo balanceamento: estruturas que abrem e fecham em pares, uma dentro da outra. Parênteses em expressões aritméticas, (2 + (3 * 4)); blocos em programação, { … }, begin … end, if … then … else.
  • Por isso as LLC são a base dos parsers.
  • Dois formalismos descrevem as LLC, um de cada lado: a GLC gera as palavras; o autômato com pilha reconhece.
  • "Contexto" são os símbolos em volta da variável. Como o lado esquerdo é só A, a variável pode ser trocada não importa o que está em volta dela.
  • Compare com uma regra sensível ao contexto, como aAb → aab: ali A só pode virar a quando está entre um a e um b.
  • Toda gramática regular também é livre do contexto. A volta é falsa: S → aSb é GLC e gera aⁿbⁿ, que não é regular.
A → α onde A ∈ V e α ∈ (V ∪ T)*
  • Do lado esquerdo, exatamente uma variável sozinha; do lado direito, qualquer sequência de variáveis e terminais, inclusive vazia (ε).
  • Duplo balanceamento (a gramática de aⁿbⁿ do exemplo do livro): o a e o b entram juntos pela mesma regra, então ficam "casados" e a quantidade é sempre igual. É assim que a GLC faz o que o AFD não consegue.
  • Expressões aritméticas: E → E+E | E*E | (E) | x gera x, x*(x+x), ((x))… E é "uma expressão" e x representa um número qualquer.

GLC: toda regra é A → α, com uma única variável sozinha do lado esquerdo. LLC = gerada por GLC = reconhecida por AP.

BNF: a mesma GLC com outra roupa

A Backus-Naur Form (BNF) é uma GLC escrita de um jeito mais legível. É a notação usada para especificar linguagens de programação desde a linguagem ALGOL, nos anos 1960.

  • Variáveis entre ⟨ ⟩, com nomes que dizem o que são.
  • ::= no lugar de →.
⟨expr⟩ ::= ⟨expr⟩ + ⟨expr⟩ | ⟨expr⟩ * ⟨expr⟩ | ( ⟨expr⟩ ) | x

Árvore de derivação e gramática ambígua

A árvore de derivação é o desenho de uma derivação: a raiz é a variável inicial, e cada variável trocada ganha como filhos os símbolos da regra usada. As folhas (as pontas de baixo), lidas da esquerda para a direita, formam a palavra.

  • A árvore ignora a ordem em que as regras foram aplicadas e mostra só a estrutura, isto é, quem está dentro de quem.
  • Se uma mesma palavra tem duas árvores diferentes, a gramática é ambígua. Isso é ruim para um compilador.
  • Com E → E+E | E*E | (E) | x, x+x*x pode virar (x+x)*x ou x+(x*x), que dão resultados diferentes. Compare os dois botões "x+x*x" da figura.

Pilha: empilhar e desempilhar

Uma pilha é como uma pilha de pratos: você só coloca e tira pratos de cima. Cabe quantos quiser, mas só o de cima é acessível.

  • Empilhar (push): coloca um símbolo no topo. Desempilhar (pop): tira o símbolo do topo.
  • O último a entrar é o primeiro a sair. Isso combina com balanceamento: o último ( aberto é o primeiro a ser fechado.

Autômato com pilha (AP)

Um autômato com pilha (AP, ou PDA em inglês) é um autômato finito não determinístico com uma pilha como memória extra. Do jeito que o professor resumiu: um AP é um AFN com memória infinita, mas só o topo dessa memória é acessível.

  • O autômato finito falhou com aⁿbⁿ por falta de memória. A pilha é essa memória extra, de um tipo bem específico.
  • O não determinismo funciona como no AFN: ver computação não determinística.
  • Um AP é descrito por seis coisas: os estados, as letras que ele lê, os símbolos que ele pode guardar na pilha, as regras de movimento, onde ele começa e onde ele aceita.
  • Teorema central: uma linguagem é livre do contexto se e somente se algum autômato com pilha a reconhece. GLC (gerador) e AP (reconhecedor) têm exatamente o mesmo poder: tudo que uma faz, o outro também faz.
M = (Q, Σ, Γ, δ, q₀, F) com δ: Q × Σ_ε × Γ_ε → 𝒫(Q × Γ_ε)
  • Uma 6-upla. Q: o conjunto (finito) de estados. q₀: o estado inicial. F ⊆ Q: os estados de aceitação. Σ: o alfabeto de entrada (as letras da palavra).
  • Γ (gama): o alfabeto da pilha, os símbolos que podem ir para a pilha. Pode ter símbolos que não estão em Σ, como $ ou A.
  • δ recebe três coisas (o estado atual, a letra lida ou ε, o símbolo do topo da pilha ou ε) e devolve um conjunto de opções de (próximo estado, o que empilhar).
  • × forma pares ou trios (um estado, uma letra, um símbolo). Σ_ε e Γ_ε incluem a opção ε, como no AFN. 𝒫(…) é "um conjunto qualquer de…", e é isso que permite várias opções ao mesmo tempo.

Lendo uma transição a, b → c e o marcador $

No desenho do AP, cada seta tem um rótulo a, b → c: lê a da entrada, tira b do topo da pilha e coloca c no lugar. Qualquer um dos três pode ser ε, que aqui quer dizer "nada".

  • Os três valores vêm sempre nesta ordem: lido da fita, desempilhado, empilhado.
  • Para a seta ser usada, duas condições valem ao mesmo tempo: o próximo símbolo da fita é o pedido e o topo da pilha é o pedido.
  • Uma transição que não lê nada (com ε na entrada) é uma ε-transição.
  • O AP não tem um teste "a pilha está vazia?". O truque é empilhar um $ logo no começo: quando o $ aparece no topo, a pilha está vazia.

Transição a, b → c: lê a, desempilha b, empilha c (cada um pode ser ε). Use $ para saber quando a pilha está vazia.

  • Se o topo não bate com o pedido, aquela seta não pode ser usada naquele momento, mesmo que o símbolo da fita bata.

Computação: configurações (⊢) e critérios de aceitação

Uma configuração (ou descrição instantânea, ID) é uma fotografia da máquina: (q, w, γ) = (estado atual, o que falta ler, conteúdo da pilha).

  • Convenção do vídeo: a pilha é escrita deitada, com o topo à direita. $AA quer dizer $ no fundo e A no topo.
  • Um passo da máquina se escreve com o símbolo ⊢ (catraca). ⊢* é zero ou mais passos.
  • Como pode haver várias opções, a execução vira uma árvore de ramos: ramos que travam (nenhuma seta possível) morrem.
  • Aceitação por estado final: algum ramo lê a entrada toda e termina num estado de F. O que sobrou na pilha não importa. É o critério usado nas figuras.
  • Aceitação por pilha vazia: algum ramo lê a entrada toda e deixa a pilha vazia.
  • Para APs não determinísticos, os dois critérios reconhecem as mesmas linguagens.
(q2, abb, $A) ⊢ (q3, bb, $)

AP para { aⁿbⁿ | n ≥ 0 }. Troque a entrada na figura e acompanhe a pilha:

  • Com aabbb, sobra um b quando a pilha já está no $: não há seta b, $ → …, o ramo morre.
  • Com abab, depois de ir para q3 não existe seta lendo a. Rejeita.
  • q1 é de aceitação para aceitar ε (o caso n = 0).

Projetando APs: palíndromos wwᴿ, aⁱbʲcᵏ e 0ⁿ1²ⁿ

Projetar um AP é responder duas perguntas: o que eu preciso lembrar, e em que ordem vou conferir? A pilha devolve as coisas na ordem inversa, então ela é perfeita para conferir algo "espelhado".

  • Comece empilhando $. Termine com ε, $ → ε indo para o estado final.
  • Use um estado por "fase" da palavra (lendo a, lendo b, lendo c).
  • "Ou" na definição da linguagem costuma virar dois ramos não determinísticos.
  • Um AP determinístico (sem escolhas, uma única opção por passo) não consegue reconhecer wwᴿ. Para APs o não determinismo dá mais poder; para autômatos finitos, não dava.
  • As linguagens que o AP determinístico reconhece são as LLC determinísticas, uma subclasse importante do Tipo 2. São elas que os parsers de compiladores usam (gramáticas LL(k) e LR(k)).

Palíndromos pares { wwᴿ }:

  • Empilha cada símbolo da primeira metade. No meio, passa para o estado de conferência.
  • Cada símbolo da segunda metade tem que ser igual ao topo da pilha; se for, desempilha.
  • Como saber onde é o meio? A máquina não sabe: ela chuta, usando uma ε-transição. Como é não determinística, tenta todos os chutes ao mesmo tempo, e basta um ramo acertar.

{ aⁱbʲcᵏ | i = j ou i = k }: alguns a, depois alguns b, depois alguns c, e o número de a é igual ao de b ou igual ao de c. Ex.: aabbc (2 a, 2 b) e aabcc (2 a, 2 c).

  • Empilha os a.
  • Chuta qual igualdade vai testar: o ramo de cima confere a com b (e ignora os c); o de baixo ignora os b e confere a com c.

{ 0ⁿ1²ⁿ | n ≥ 1 }, dois 1 para cada 0 (exercício da aula). Ex.: 011, 001111, 000111111.

  • Cada 0 empilha um X. Depois os 1 vêm em pares: o primeiro do par só é lido, o segundo desempilha um X.
  • Outra saída: empilhar dois X por 0 e desempilhar um por 1. Como cada transição empilha um símbolo só, isso pede um estado intermediário.

Na figura, escolha a máquina (são os três exercícios possíveis da aula). A contagem final mostra quantas configurações o simulador explorou: são os ramos do não determinismo.

  • aⁿbⁿcⁿ (mesmo número de a, b e c) não tem AP. Contar duas coisas ao mesmo tempo contra uma terceira não cabe numa pilha só: é o sinal de que a linguagem não é livre do contexto, e a pegadinha da lista de exercícios da aula.

Máquina de Turing, ALL e decidibilidade

A máquina de Turing (MT) é um autômato com uma fita infinita onde ele pode ler, escrever e andar para os dois lados. É o modelo teórico de "qualquer computador": tudo que um programa consegue calcular, uma MT também consegue.

  • Autômato linearmente limitado (ALL): uma MT que só pode usar a parte da fita onde está a palavra de entrada. Memória proporcional ao tamanho da entrada, em vez de infinita.
  • Reconhecer é diferente de decidir: uma MT pode aceitar as palavras da linguagem mas rodar para sempre nas que não são. Quando ela sempre para com sim ou não, a linguagem é decidível.
  • Problema da parada (dado um programa e uma entrada, ele termina?): dá para reconhecer os casos em que termina (é só rodar e esperar), mas não existe programa que decida todos os casos.

Hierarquia de Chomsky

Noam Chomsky (linguista) classificou as gramáticas pelo formato das regras: quanto mais restrita a regra, menor a classe de linguagens que ela gera. Cada classe tem uma máquina que a reconhece, e o mapa amarra toda a matéria.

  • As inclusões são próprias (⊊, ver conjuntos): todo Tipo 3 é Tipo 2, todo Tipo 2 é Tipo 1, e assim por diante, mas sempre existe uma linguagem no anel de fora que não está no de dentro.
  • Ao subir de tipo, a máquina ganha memória: nenhuma (AF) → pilha (AP) → fita do tamanho da entrada (ALL) → fita infinita (MT).
  • Sensíveis ao contexto (Tipo 1): regras α → β com |α| ≤ |β|, a palavra nunca encolhe.
  • Recursivamente enumerável (Tipo 0) é o nome técnico de "existe uma máquina de Turing que aceita as palavras dela". É a classe mais ampla que uma máquina consegue alcançar.
  • Fora do Tipo 0 ainda existem linguagens que nenhuma máquina de Turing reconhece.
  • Para separar Tipo 3 de Tipo 2 usamos o lema do bombeamento (aⁿbⁿ). Para separar Tipo 2 de Tipo 1 existe um lema do bombeamento para LLC (aⁿbⁿcⁿ).
  • Por que ww não é livre do contexto: a pilha devolve a primeira metade invertida, e comparar na mesma ordem pediria uma segunda pilha. Em compiladores, é o mesmo tipo de problema que conferir se uma variável foi declarada antes de ser usada.
Tipo 3 ⊊ Tipo 2 ⊊ Tipo 1 ⊊ Tipo 0

Tipo 3 ⊊ 2 ⊊ 1 ⊊ 0, com AF, AP, ALL e MT. Saiba um exemplo que separa cada nível: aⁿbⁿ é LLC e não regular; aⁿbⁿcⁿ é sensível ao contexto e não LLC.

Compilador: análise léxica, sintática e semântica

Um compilador traduz um programa e, antes disso, confere se o código está escrito na estrutura certa. Na aula, cada nível da hierarquia foi ligado a uma etapa dele.

  • Análise léxica, a primeira etapa: reconhece as palavras do código. Base: linguagens regulares e autômatos finitos.
  • Análise sintática, feita pelo parser (analisador sintático): confere a ordem das palavras, se o programa está escrito na estrutura certa, antes de traduzi-lo. Base: livres do contexto.
  • Análise semântica: por trás dela estão as sensíveis ao contexto (dá para fazê-la sem se aprofundar nelas).
