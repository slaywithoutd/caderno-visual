01

Antes de começar: conjuntos e notação

Base · fora dos autoestudos

Os vídeos e o livro escrevem quase tudo com notação de conjuntos e não param para explicar. Esta seção é o "dicionário" para ler o resto. Se você já domina, pule para a seção 2.

Conjunto é um saco de coisas. B está dentro de A: B é subconjunto de A.

Conjuntos

  • Conjunto: uma coleção de coisas, sem ordem e sem repetição. Escreve-se entre chaves: {a, b} é o mesmo que {b, a}.
  • x ∈ A: "x pertence a A", x é um dos elementos de A. x ∉ A: não pertence.
  • B ⊆ A: B é subconjunto de A, tudo que está em B também está em A. B ⊊ A: subconjunto e A tem algo a mais.
  • ∅ ou { }: o conjunto vazio, sem nenhum elemento.
  • A ∪ B (união): o que está em A ou em B. A ∩ B (interseção): o que está nos dois. A − B: o que está em A e não em B.
  • Um conjunto pode ser finito (dá para listar tudo) ou infinito (a lista nunca acaba, como os números naturais).

Descrever um conjunto por uma regra

Quando o conjunto é infinito, não dá para listar. Usa-se a forma { x | condição }, que se lê "o conjunto dos x tais que a condição vale".

{ aⁿbⁿ | n ≥ 0 } = { ε, ab, aabb, aaabbb, … }
  • Lê-se: "as palavras formadas por n letras a seguidas de n letras b, para todo n a partir de 0".
  • aⁿ aqui não é potência de número: é "a letra a repetida n vezes". a³ = aaa.
  • n ≥ 0 diz quais valores n pode assumir.

02

Alfabeto, palavra e linguagem

Menezes · cap. 2 · p. 54–58
Alfabeto é o conjunto de peças; palavra é uma fila finita delas. ε é o fio sem contas.

A matéria inteira trata de uma pergunta: quais sequências de símbolos são válidas? Um compilador faz isso com programas, um validador de e-mail faz com endereços. Para estudar isso com precisão, a teoria começa com três peças.

  • Símbolo: qualquer marca que dá para distinguir de outra. Uma letra, um dígito, um sinal: a, 0, +. A teoria não define símbolo além disso.
  • Alfabeto (Σ): o conjunto de símbolos que podem ser usados. Precisa ser finito. Ex.: Σ = {a, b} ou Σ = {0, 1}.
  • Palavra (também chamada cadeia ou sentença): uma sequência finita de símbolos do alfabeto, um do lado do outro. Ex.: abba. A ordem importa: ab ≠ ba.
  • Palavra vazia (ε): a sequência com zero símbolos. Parece estranho, mas é como a string "" em programação. Alguns livros escrevem λ.
  • Comprimento (|w|): quantos símbolos a palavra tem. |abba| = 4, |ε| = 0.
Toda linguagem é um recorte de Σ*. Aqui, L = palíndromos.

Agora junte todas as palavras que dá para formar com um alfabeto. Esse conjunto tem nome:

  • Σ* (lê-se "sigma estrela"): todas as palavras possíveis sobre Σ, de qualquer tamanho, incluindo ε. É sempre infinito (se Σ tiver pelo menos um símbolo), mas cada palavra dentro dele é finita.
  • Σ⁺ ("sigma mais"): o mesmo, sem a palavra vazia. Σ⁺ = Σ* − {ε}.
Definição · Linguagem formal

Uma linguagem é uma escolha de palavras: um grupo de palavras que você considera "válidas". As outras ficam de fora.

Uma linguagem formal L sobre Σ é qualquer subconjunto de Σ*, ou seja, L ⊆ Σ*. Pode ser finita, infinita ou vazia.

  • Exemplo: com Σ = {a, b}, "as palavras que começam com a" é uma linguagem: {a, aa, ab, aaa, …}.
  • Σ* e Σ⁺ também são linguagens sobre Σ.
  • Uma linguagem de programação é o conjunto de todos os programas válidos. Cada programa é uma palavra (bem longa) sobre o alfabeto dos caracteres do teclado.

∅ ≠ {ε}: ∅ não tem nenhuma palavra; {ε} tem exatamente uma, a vazia. As duas são linguagens.

Prefixo = começo, sufixo = fim, subpalavra = qualquer pedaço contínuo.

Prefixo, sufixo e subpalavra

  • Prefixo: um pedaço do começo da palavra. Prefixos de abb: ε, a, ab, abb.
  • Sufixo: um pedaço do fim. Sufixos de abb: ε, b, bb, abb.
  • Subpalavra: qualquer pedaço contínuo de dentro da palavra, sem pular letras. bb é subpalavra de abba; aa não é (teria que pular os b).
  • Toda palavra é prefixo, sufixo e subpalavra de si mesma, e ε também é as três coisas.
Versão formal (como está no livro)

y é subpalavra de w se existem palavras x e z com w = xyz. Prefixo é o caso em que x = ε; sufixo, quando z = ε. Por isso o livro diz "subpalavra é qualquer prefixo de um sufixo": corte um fim e depois um começo, sobra um pedaço do meio.

Concatenação: juntar palavras

A ordem dos vagões importa: ab·ba ≠ ba·ab.
  • Concatenação vw (às vezes v·w): escreve v e logo depois w. Se v = ab e w = ba, então vw = abba. É o + de strings em programação.
  • Associativa: tanto faz por onde você começa a juntar. (ab·c)·d = ab·(c·d) = abcd.
  • ε é o elemento neutro: juntar com nada não muda nada. εw = wε = w.
  • Não é comutativa: trocar a ordem muda o resultado. ab·ba = abba, mas ba·ab = baab.
  • O tamanho soma: |vw| = |v| + |w|.
  • Concatenação sucessiva wⁿ: w repetida n vezes. (ab)³ = ababab. Por definição, w⁰ = ε (repetir zero vezes dá a palavra vazia).
  • Reverso wᴿ: a palavra de trás para frente. Se w = abc, wᴿ = cba. Um palíndromo é uma palavra igual ao próprio reverso, como abba.

Operações sobre linguagens

Linguagens são conjuntos de palavras, então dá para fazer com elas tudo que se faz com conjuntos, e mais duas operações próprias:

  • União, interseção, diferença: L₁ ∪ L₂ (palavras que estão em uma ou na outra), L₁ ∩ L₂ (nas duas), L₁ − L₂ (na primeira e não na segunda).
  • Concatenação de linguagens L₁L₂: todas as combinações "uma palavra de L₁ seguida de uma de L₂". Ex.: {a, b}·{c} = {ac, bc}. Formalmente L₁L₂ = { uv | u ∈ L₁ e v ∈ L₂ }.
  • Fecho de Kleene L*: juntar palavras de L quantas vezes quiser, inclusive nenhuma. Se L = {ab}, então L* = {ε, ab, abab, …}. Formalmente L* = L⁰ ∪ L¹ ∪ L² ∪ …, com L⁰ = {ε}. É o mesmo "*" de Σ*.

03

Gramáticas: regras que geram palavras

Menezes · cap. 2 · p. 58–63
Uma descrição finita que fabrica infinitas palavras.

Uma linguagem infinita não cabe numa lista. Precisamos de uma descrição finita que consiga produzir todas as palavras dela, e nenhuma outra. A gramática é essa descrição.

Definição · Gramática

Uma gramática é uma receita de substituições. Você começa com um símbolo especial e vai trocando pedaços seguindo as regras, até sobrar só letras "de verdade". Cada resultado possível é uma palavra da linguagem.

Uma gramática é uma quádrupla G = (V, T, P, S):

  • V: as variáveis (ou não-terminais), símbolos de rascunho que ainda vão ser trocados. Escritas em maiúscula; aqui em azul: S, N, D, E.
  • T: os terminais, os símbolos que aparecem na palavra final (o alfabeto da linguagem). V e T não têm símbolo em comum.
  • P: as regras de produção, escritas α → β e lidas "α pode ser trocado por β". α e β são sequências de variáveis e terminais; α tem pelo menos uma variável.
  • S: a variável inicial, de onde tudo começa (S ∈ V).
Cada ⇒ é um passo. Termina quando não sobra variável (azul).
  • Abreviação: S → aSb | ε são duas regras, S → aSb e S → ε. A barra | se lê "ou".
  • Passo de derivação (⇒): aplicar uma regra uma vez. Exemplo: com a regra S → aSb, a sequência aSb vira aaSbb (trocamos o S do meio). Escreve-se aSb ⇒ aaSbb.
  • Na forma geral do livro: se α → β é uma regra, então uαv ⇒ uβv. Ou seja, o que está em volta (u e v) fica igual; só o pedaço α é trocado.
  • ⇒*: zero ou mais passos. ⇒⁺: um ou mais passos.
  • Forma sentencial: qualquer sequência que aparece no meio do caminho, misturando variáveis e terminais, como aaSbb.
  • Derivação mais à esquerda: em cada passo, troca-se a variável mais à esquerda. É só uma convenção para todos fazerem na mesma ordem.

Definição · Linguagem gerada

A linguagem de uma gramática é o conjunto de todas as palavras que dá para fabricar com ela, começando em S e parando quando só sobram terminais.

O livro escreve GERA(G) ou L(G):

L(G) = { w ∈ T* | S ⇒⁺ w }

Lê-se: "as palavras w feitas só de terminais tais que, partindo de S, chega-se em w em um ou mais passos".

  • Exemplo do livro, duplo balanceamento: G = ({S}, {a,b}, {S → aSb, S → ε}, S) gera { aⁿbⁿ | n ≥ 0 } = {ε, ab, aabb, aaabbb, …}. Cada uso de S → aSb coloca um a e um b ao mesmo tempo; por isso a quantidade é sempre igual.
  • Exemplo do livro, números naturais: N → D | DN e D → 0 | 1 | … | 9 geram qualquer sequência de dígitos. N é "um número" e D é "um dígito".
  • Duas gramáticas são equivalentes se geram a mesma linguagem, L(G₁) = L(G₂), mesmo com regras diferentes.
Gerar × reconhecer
  • Um formalismo é um jeito preciso, com regras fixas, de descrever uma linguagem.
  • A gramática é um formalismo gerador: ela fabrica as palavras.
  • Um autômato (uma máquina abstrata, que aparece na próxima seção) é um formalismo reconhecedor: recebe uma palavra e responde "sim, pertence" ou "não pertence".
  • A matéria toda gira em torno de qual gramática corresponde a qual máquina. O mapa completo é a Hierarquia de Chomsky, na seção 8.

O limite das linguagens regulares

Vídeo · LFA Aula 11 · Linguagens não-regulares ↗

O vídeo é a aula 11 de outro curso e começa assumindo que você já viu autômatos finitos e linguagens regulares. A caixa abaixo resume o que ele pressupõe.

Base Autômato finito e linguagem regular em 3 minutos
em loopEste AFD aceita as palavras que terminam em a. Ele lê "baba" letra por letra e termina em q1, um estado final.
  • Um autômato finito (AF) é uma máquina bem simples que lê uma palavra da esquerda para a direita, uma letra por vez, e no fim diz aceito ou rejeito.
  • Ela tem um número finito de estados (desenhados como círculos: q0, q1…). Estar num estado é a única coisa que ela "lembra".
  • As transições (setas) dizem: "estando no estado q, se ler a letra x, vá para o estado r".
  • Um estado é o estado inicial (seta solta apontando para ele). Alguns são estados finais (círculo duplo).
  • A palavra é aceita se, depois de ler tudo, a máquina está num estado final.
  • AFD (determinístico): para cada estado e letra existe exatamente uma seta. AFN (não determinístico): pode haver várias opções, ou nenhuma; a palavra é aceita se alguma escolha de caminho termina num estado final. Os dois reconhecem exatamente as mesmas linguagens.
Definição · Linguagem regular

Uma linguagem é regular quando dá para construir um autômato finito que aceita exatamente as palavras dela.

L é regular ⇔ existe um AF M com L(M) = L. Equivalente: existe uma expressão regular que descreve L, como a*b* ("zero ou mais a, depois zero ou mais b"; o * quer dizer "repita quantas vezes quiser, inclusive nenhuma").

em loopO AFD leu vários a, mas só sabe em qual estado está. Contar até n exigiria n estados.

O ponto fraco do autômato finito é a memória: ele só sabe em qual estado está, e o número de estados é fixo. Isso cria um limite do que ele consegue reconhecer.

  • Um AFD com 5 estados consegue distinguir no máximo 5 "situações".
  • Para reconhecer aⁿbⁿ, ele precisaria lembrar quantos a leu, para depois conferir os b. Esse número pode ser 6, 100, um bilhão… não cabe numa quantidade fixa de estados.
  • Conclusão intuitiva: linguagens que exigem contar sem limite ou casar pares não são regulares.

Exemplos clássicos de linguagens não-regulares

  • { aⁿbⁿ | n ≥ 0 }: a mesma quantidade de a e b, com os a antes. No vídeo aparece como 0ⁿ1ⁿ: é a mesma linguagem com outros símbolos.
  • { wwᴿ | w ∈ {a,b}* }: uma palavra seguida do seu reverso, ou seja, palíndromos de tamanho par (abba, aa).
  • Parênteses balanceados: (()(())). Cada ( precisa de um ) depois.
  • { w | w tem o mesmo número de a e b }, em qualquer ordem.
  • { aᵖ | p é primo } e { ww | w ∈ {a,b}* } (uma palavra repetida duas vezes, como abab).
Pegadinha do vídeo

"Tem que contar" precisa ser contagem ilimitada que será comparada depois. A linguagem das cadeias binárias com o mesmo número de ocorrências de 01 e de 10 parece exigir contagem, mas é regular: essas ocorrências se alternam, então basta saber o primeiro e o último símbolo. Um AFD faz isso com poucos estados.

Ler p símbolos visita p+1 estados. Com p estados, algum repete.

Intuição não é prova. A ferramenta para provar é o lema do bombeamento. Ele vem de uma observação simples, o princípio da casa dos pombos: se 4 pombos entram em 3 casas, alguma casa fica com 2. No autômato, os "pombos" são os passos de leitura e as "casas" são os estados. Se a palavra é maior do que o número de estados, algum estado é visitado duas vezes, e o trecho lido entre as duas visitas é um laço que dá para repetir.

em loopCom 0, 1, 2 ou 3 voltas no laço y, o caminho ainda termina aceitando.
Lema do bombeamento · linguagens regulares

Em toda linguagem regular, qualquer palavra comprida o bastante tem, perto do começo, um pedaço que você pode repetir quantas vezes quiser (ou apagar) e a palavra continua na linguagem.

Se L é regular, então existe um número p (o comprimento de bombeamento) tal que toda palavra w ∈ L com |w| ≥ p pode ser dividida em três pedaços w = xyz com:

  • |y| ≥ 1: o pedaço repetível tem pelo menos uma letra;
  • |xy| ≤ p: ele está entre as p primeiras letras;
  • xyⁱz ∈ L para todo i ≥ 0: repetir y i vezes (ou apagar, com i = 0) mantém a palavra em L. xy²z = xyyz.

Pense em p como o número de estados do AFD: palavras com p letras ou mais obrigatoriamente passam por um laço.

Para que serve

  • O lema diz: "se é regular, então é bombeável". Ele não serve para provar que algo é regular.
  • Ele serve pelo caminho inverso, a contrapositiva: "se não é bombeável, não é regular". É a mesma lógica de "se choveu, a rua está molhada; a rua está seca, então não choveu".
  • A prova é feita por contradição: você supõe que L é regular, aplica o lema e chega numa coisa impossível. Logo a suposição era falsa.

O lema do bombeamento só prova que uma linguagem não é regular. Para aⁿbⁿ: escolha w = aᵖbᵖ; como |xy| ≤ p, y só tem a, e xy²z sai de L.

Receita: provar que L não é regular

Ele joga 1 e 3, você joga 2 e 4. Você ganha se vencer toda divisão.

Pense num jogo contra um adversário que defende que L é regular. Onde o lema diz "existe", quem escolhe é ele; onde diz "para todo", você precisa ganhar em qualquer caso.

  • 1. Adversário escolhe p. Você não sabe o valor, então trata p como um número qualquer.
  • 2. Você escolhe uma palavra w ∈ L com |w| ≥ p. Escolha uma que deixe o adversário sem saída. Para aⁿbⁿ: w = aᵖbᵖ (p letras a seguidas de p letras b).
  • 3. Adversário divide w = xyz respeitando |y| ≥ 1 e |xy| ≤ p. Você precisa considerar todas as divisões possíveis.
  • 4. Você escolhe um i e mostra que xyⁱz ∉ L.
  • Como funcionou para toda divisão, L não satisfaz o lema. Contradição: L não é regular.

Jogue com aⁿbⁿ. Mexa em p, tente esconder y onde quiser e veja se escapa:

Erros comuns
  • Escolher um p específico (ex.: "seja p = 3"). Quem escolhe p é o adversário.
  • Escolher você mesmo a divisão xyz. Você tem que derrotar todas.
  • Escolher w curta demais ou fora de L.
  • Achar que "passar no lema" prova que L é regular. Existem linguagens não-regulares que passam.

Fechamento do vídeo: se nem aⁿbⁿ cabe num autômato finito, precisamos de algo mais forte. As gramáticas livres do contexto (para gerar) e os autômatos com pilha (para reconhecer) resolvem exatamente esse tipo de linguagem.

05

Linguagens livres do contexto

Menezes · cap. 6 · p. 153–156
Duplo balanceamento: o último que abriu é o primeiro a fechar.

As linguagens livres do contexto (LLC) são uma classe maior que a das regulares: toda linguagem regular é LLC, e algumas LLC (como aⁿbⁿ) não são regulares. O exemplo típico é o duplo balanceamento: estruturas que abrem e fecham em pares, uma dentro da outra.

  • Parênteses em expressões aritméticas: (2 + (3 * 4)).
  • Blocos em programação: { … }, begin … end, if … then … else.
  • Por isso as LLC são a base dos analisadores sintáticos (parsers): a parte do compilador que confere se o programa está escrito na estrutura certa, antes de traduzi-lo.

Dois formalismos descrevem as LLC, um de cada lado:

  • Gramática livre do contexto (GLC): gera as palavras.
  • Autômato com pilha (AP): reconhece. É um autômato finito com uma pilha como memória extra (seção 6).
Definição · Gramática livre do contexto

É uma gramática em que toda regra troca uma única variável por alguma coisa. Nada de regras do tipo "troque aAb por…".

Uma gramática G = (V, T, P, S) em que toda regra tem a forma

A → α   onde A ∈ V e α ∈ (V ∪ T)*

Lê-se: do lado esquerdo, exatamente uma variável sozinha; do lado direito, qualquer sequência de variáveis e terminais, inclusive vazia (ε).

Linguagem livre do contexto = linguagem gerada por alguma GLC.

GLC: toda regra é A → α, com uma única variável sozinha do lado esquerdo. LLC = gerada por GLC = reconhecida por AP.

Por que "livre do contexto"?

Em cima, A troca em qualquer lugar. Embaixo, só entre a e b.
  • "Contexto" aqui são os símbolos em volta da variável.
  • Como o lado esquerdo é só A, a variável pode ser trocada não importa o que está em volta dela.
  • Compare com uma regra sensível ao contexto como aAb → aab: ali A só pode virar a quando está entre um a e um b.
  • Toda gramática regular (regras só do tipo A → aB ou A → a, que geram exatamente as linguagens regulares) também é livre do contexto. A volta é falsa: S → aSb é GLC e gera aⁿbⁿ, que não é regular.

Exemplos do livro

  • Duplo balanceamento: S → aSb | ε gera { aⁿbⁿ | n ≥ 0 }. O a e o b entram juntos pela mesma regra, então ficam "casados". É assim que a GLC faz o que o AFD não consegue.
  • Expressões aritméticas: E → E+E | E*E | (E) | x gera x, x*(x+x), ((x))… Aqui E é "uma expressão" e x representa um número qualquer.

BNF: a mesma coisa com outra roupa

Mesma gramática: só muda a notação.

A Backus-Naur Form (BNF) é a notação usada para especificar linguagens de programação desde a linguagem ALGOL, nos anos 1960. Ela é uma GLC escrita de um jeito mais legível:

  • variáveis entre ⟨ ⟩, com nomes que dizem o que são;
  • ::= no lugar de →.
⟨expr⟩ ::= ⟨expr⟩ + ⟨expr⟩ | ⟨expr⟩ * ⟨expr⟩ | ( ⟨expr⟩ ) | x

Árvore de derivação

  • É o desenho de uma derivação. A raiz é a variável inicial; cada variável trocada ganha como filhos os símbolos da regra usada.
  • As folhas (as pontas de baixo), lidas da esquerda para a direita, formam a palavra.
  • A árvore ignora a ordem em que as regras foram aplicadas e mostra só a estrutura, isto é, quem está dentro de quem.
  • Se uma mesma palavra tem duas árvores diferentes, a gramática é ambígua. Isso é ruim para um compilador: x+x*x pode virar (x+x)*x ou x+(x*x), que dão resultados diferentes. Compare os dois botões "x+x*x" abaixo.
06

Autômatos com pilha

Vídeo · Autômatos com pilha ↗
em loopCada a empilha um A; cada b tira um. Sobrou só o $: mesma quantidade.

O autômato finito falhou com aⁿbⁿ por falta de memória. A solução é dar a ele uma memória extra, mas de um tipo bem específico: uma pilha.

  • Uma pilha é como uma pilha de pratos: você só coloca e tira pratos de cima. Cabe quantos quiser, mas só o de cima é acessível.
  • Empilhar (push): coloca um símbolo no topo. Desempilhar (pop): tira o símbolo do topo.
  • O último a entrar é o primeiro a sair. Isso combina com balanceamento: o último ( aberto é o primeiro a ser fechado.

Um autômato com pilha (AP, ou PDA em inglês) é um autômato finito não determinístico com uma pilha. Lembrando da caixa da seção 4: não determinístico quer dizer que, em algum momento, a máquina pode ter mais de uma opção, e a palavra é aceita se alguma sequência de escolhas der certo.

Definição formal (notação do vídeo)

Um AP é descrito por seis coisas: os estados, as letras que ele lê, os símbolos que ele pode guardar na pilha, as regras de movimento, onde ele começa e onde ele aceita.

Um AP é uma 6-upla M = (Q, Σ, Γ, δ, q₀, F):

  • Q: o conjunto (finito) de estados. q₀: o estado inicial. F ⊆ Q: os estados de aceitação.
  • Σ: o alfabeto de entrada (as letras da palavra).
  • Γ (gama): o alfabeto da pilha, os símbolos que podem ir para a pilha. Pode ter símbolos que não estão em Σ, como $ ou A.
  • δ (delta): a função de transição, as regras de movimento. Ela recebe três coisas (o estado atual, a letra lida ou ε, o símbolo do topo da pilha ou ε) e devolve um conjunto de opções de (próximo estado, o que empilhar).

No livro isso aparece como δ: Q × Σ_ε × Γ_ε → 𝒫(Q × Γ_ε). Tradução: × forma pares ou trios (um estado, uma letra, um símbolo); Σ_ε é Σ mais a opção ε ("não ler nada"); 𝒫(…) é o conjunto das partes, "um conjunto qualquer de…", e é isso que permite várias opções ao mesmo tempo.

Lendo uma transição a, b → c

Qualquer um dos três pode ser ε (não faz nada).

No desenho do AP, cada seta tem um rótulo a, b → c: "lê a da entrada, tira b do topo da pilha e coloca c no lugar". Qualquer um dos três pode ser ε, que aqui quer dizer "nada":

RótuloO que fazUso típico
a, ε → Alê a, não tira nada, empilha Acontar / guardar
b, A → εlê b, desempilha A, não empilhacasar / cancelar
ε, ε → $não lê nada, empilha $marcar o fundo da pilha
ε, $ → εnão lê, desempilha $testar "pilha vazia" antes de aceitar
a, ε → εsó lê aignorar símbolos
  • Se o topo da pilha não for o símbolo pedido, aquela seta não pode ser usada naquele momento.
  • Uma transição que não lê nada (com ε na entrada) é uma ε-transição: a máquina muda de estado "de graça".
  • O AP não tem um teste "a pilha está vazia?". O truque é empilhar um $ logo no começo: quando o $ aparece no topo, a pilha está vazia.

Transição a, b → c: lê a, desempilha b, empilha c (cada um pode ser ε). Use $ para saber quando a pilha está vazia.

Computação: configurações

Uma fotografia completa da máquina num instante.
  • Uma configuração (ou descrição instantânea, ID) é uma fotografia da máquina: (q, w, γ) = (estado atual, o que falta ler, conteúdo da pilha).
  • Convenção do vídeo: a pilha é escrita deitada, com o topo à direita. $AA quer dizer $ no fundo e A no topo.
  • Um passo da máquina se escreve com o símbolo ⊢ (catraca): (q2, abb, $A) ⊢ (q3, bb, $). ⊢* é zero ou mais passos.
  • Como pode haver várias opções, a execução vira uma árvore de ramos: cada escolha abre um caminho. Ramos que travam (nenhuma seta possível) simplesmente morrem.
Dois critérios de aceitação
  • Por estado final: algum ramo lê a entrada toda e termina num estado de F. O que sobrou na pilha não importa. É o critério usado nas figuras.
  • Por pilha vazia: algum ramo lê a entrada toda e deixa a pilha vazia.
  • Para APs não determinísticos, os dois critérios reconhecem as mesmas linguagens.

O AP abaixo reconhece { aⁿbⁿ | n ≥ 0 }. Troque a entrada e acompanhe a pilha:

  • Com aabbb, sobra um b quando a pilha já está no $: não há seta b, $ → …, o ramo morre.
  • Com abab, depois de ir para q3 não existe seta lendo a. Rejeita.
  • q1 é de aceitação para aceitar ε (o caso n = 0).

Mais exemplos: projetando APs

Vídeo · APs: mais exemplos ↗
Empilha a 1ª metade; a 2ª sai na ordem inversa e confere.

Projetar um AP é responder duas perguntas: o que eu preciso lembrar, e em que ordem vou conferir? A pilha devolve as coisas na ordem inversa, então ela é perfeita para conferir algo "espelhado".

Palíndromos pares: { wwᴿ }

  • Empilha cada símbolo da primeira metade.
  • No meio, passa para o estado de conferência.
  • Cada símbolo da segunda metade tem que ser igual ao topo da pilha; se for, desempilha.
  • O problema: como saber onde é o meio? A máquina não sabe. Ela chuta, usando uma ε-transição. Como é não determinística, ela tenta todos os chutes ao mesmo tempo, e basta um ramo acertar.
  • Um AP determinístico (sem escolhas, uma única opção por passo) não consegue reconhecer wwᴿ. Ou seja, para APs o não determinismo dá mais poder. Para autômatos finitos, não dava.
em loopO AP tenta todos os "meios" ao mesmo tempo. Só o ramo que chuta a posição 2 aceita abba.

{ aⁱbʲcᵏ | i = j ou i = k }

"Ou" vira dois ramos. Basta um aceitar.
  • A linguagem: alguns a, depois alguns b, depois alguns c, e o número de a é igual ao de b ou igual ao de c. Ex.: aabbc (2 a, 2 b) e aabcc (2 a, 2 c) estão nela.
  • Empilha os a.
  • Chuta qual igualdade vai testar: o ramo de cima confere a com b (e ignora os c); o de baixo ignora os b e confere a com c.
  • "Ou" na definição da linguagem costuma virar dois ramos não determinísticos.

Escolha a máquina. Na contagem final aparece quantas configurações o simulador explorou: são os ramos do não determinismo.

Dicas de projeto
  • Comece empilhando $. Termine com ε, $ → ε indo para o estado final.
  • Use um estado por "fase" da palavra (lendo a, lendo b, lendo c).
  • Precisa contar duas coisas ao mesmo tempo contra uma terceira (aⁿbⁿcⁿ: mesmo número de a, b e c)? Uma pilha não basta. Esse é o sinal de que a linguagem não é livre do contexto.
Teorema central

Uma linguagem é livre do contexto se e somente se algum autômato com pilha a reconhece. GLC (gerador) e AP (reconhecedor) têm exatamente o mesmo poder: tudo que uma faz, o outro também faz.

Hierarquia de Chomsky

Vídeo · LFA Aula 19 · Hierarquia de Chomsky ↗
Subir de tipo = dar mais memória à máquina.

Noam Chomsky (linguista) classificou as gramáticas pelo formato das regras. Quanto mais restrita a regra, menor a classe de linguagens que ela gera. Cada classe tem uma máquina que a reconhece. É o mapa que amarra toda a matéria.

Base As duas máquinas que ainda não apareceram
  • Máquina de Turing (MT): um autômato com uma fita infinita onde ele pode ler, escrever e andar para os dois lados. É o modelo teórico de "qualquer computador": tudo que um programa consegue calcular, uma MT também consegue.
  • Autômato linearmente limitado (ALL): uma máquina de Turing que só pode usar a parte da fita onde está a palavra de entrada. Memória proporcional ao tamanho da entrada, não infinita.
  • Reconhecer não é o mesmo que decidir: uma MT pode aceitar as palavras da linguagem mas rodar para sempre nas que não são. Quando ela sempre para com sim ou não, a linguagem é decidível.
  • O problema da parada (dado um programa e uma entrada, ele termina?) é o exemplo famoso: dá para reconhecer os casos em que termina (é só rodar e esperar), mas não existe programa que decida todos os casos.
TipoClasse de linguagensForma das regrasReconhecedorExemplo
0Recursivamente enumeráveisα → β, sem restrição (α contém variável)Máquina de Turingproblema da parada
1Sensíveis ao contextoα → β com |α| ≤ |β| (a palavra nunca encolhe)MT com fita limitada (ALL)aⁿbⁿcⁿ, ww
2Livres do contextoA → αAutômato com pilhaaⁿbⁿ, wwᴿ
3RegularesA → aB ou A → a (linear à direita)Autômato finitoa*b*

Tipo 3 ⊊ 2 ⊊ 1 ⊊ 0, com AF, AP, ALL e MT. Saiba um exemplo que separa cada nível: aⁿbⁿ é LLC e não regular; aⁿbⁿcⁿ é sensível ao contexto e não LLC.

  • As inclusões são próprias (⊊): todo Tipo 3 é Tipo 2, todo Tipo 2 é Tipo 1, e assim por diante, mas sempre existe uma linguagem no anel de fora que não está no de dentro.
  • Recursivamente enumerável é o nome técnico de "existe uma máquina de Turing que aceita as palavras dela". É a classe mais ampla que uma máquina consegue alcançar.
  • Para separar Tipo 3 de Tipo 2 usamos o lema do bombeamento da seção 4 (aⁿbⁿ). Para separar Tipo 2 de Tipo 1 existe um lema do bombeamento para LLC (aⁿbⁿcⁿ).
  • Ao subir de tipo, a máquina ganha memória: nenhuma (AF) → pilha (AP) → fita do tamanho da entrada (ALL) → fita infinita (MT).
  • Dentro do Tipo 2 há uma subclasse importante: as LLC determinísticas, reconhecidas por AP determinístico. São elas que os parsers de compiladores usam (gramáticas LL(k) e LR(k)). wwᴿ é LLC, mas não é determinística.
  • No Tipo 3, gramática regular, expressão regular, AFD, AFN e AFN-ε (AFN com ε-transições) têm todos o mesmo poder.
  • Fora do Tipo 0 ainda existem linguagens que nenhuma máquina de Turing reconhece.
