Resumo

O sintático deixa passar; o semântico consulta a tabela e recusa.

Análise semântica é a fase que anda pela árvore sintática e confere o que a gramática não consegue: se cada nome foi declarado, qual declaração vale em cada ponto e se os tipos combinam.

  • O sintático aceita x = y + 1; sem y declarado: a gramática livre de contexto não lembra nomes. Quem lembra é a tabela de símbolos, preenchida nas declarações e consultada nos usos.
  • Atributo sintetizado sobe (é o retorno da função do não terminal); atributo herdado desce (é um parâmetro). Sem recursão à esquerda, o que já foi calculado à esquerda desce como herdado: mais_fatores(herdado).
  • As verificações rodam dentro do sintático, como ações nas regras, ou depois, numa passada sobre a árvore pronta: o visitor, um método por tipo de nó.
  • Escopo estático tem duas regras: declaração antes do uso e aninhamento mais próximo. Implementação: uma pilha de tabelas, um dict por bloco, busca do topo para o fundo, e ao sair do bloco a tabela inteira é desempilhada.
  • Tipos se calculam em pós-ordem: a folha dá o tipo (pelo literal ou pela tabela), cada operador confere os filhos e devolve o seu. Uma expressão com erro devolve invalido, e a mensagem aparece uma vez só.
  • Também é do semântico: o lado esquerdo do = ser um lugar na memória, os argumentos concordarem com os parâmetros em número e tipo, break só dentro de laço.
  • Declarar o mesmo nome duas vezes é erro só no mesmo bloco. Num bloco interno é sombreamento, e vale.
  • Ao sair de um bloco, nenhum símbolo é apagado da tabela de fora: sai a tabela do bloco, e a declaração externa volta a valer.
  • Com herdado, a subtração é herdado - termo. Na ordem trocada, 10 − 3 − 2 dá 9 no lugar de 5.
  • int + real só é erro se a linguagem não converte. Com coerção, o verificador põe um nó de conversão na árvore; real guardado em variável int perde a parte decimal e costuma continuar proibido.

O semântico em Python, na classe da aula

Duas classes: uma monta a árvore, a outra anda nela.

O código abaixo pega a gramática da dinâmica de 12/11, acrescenta declarações com tipo e blocos aninhados (a Mini-bloco) e escreve duas classes: o sintático no padrão da aula, que devolve a AST, e o semântico, que anda nessa árvore com uma pilha de tabelas de símbolos e junta os erros numa lista.

  • Token(tipo, valor, linha), NoInterno(op, **kwargs), NoFolha(op, valor, linha) e o comparar que devolve o token consumido são os do exemplo da rotina do robô (ex_sintatico_arvore_desafio.py). tokenCorrente, proximoToken e analisar terminando em comparar('EOF') são os da aula 12.
  • lista_cmd devolve NoInterno('listaCmd', cmd=…, prox=…) e termina em None, como o listaAcoes do robô: a lista de comandos é uma cadeia que acaba em nulo (o nó Seq).
  • mais_fatores(herdado) recebe a árvore montada até ali e devolve a árvore maior. É o atributo herdado que deixa 1 + 2 + 3 associativo à esquerda sem recursão à esquerda.
  • O semântico guarda escopos (uma lista de dicts; o último é o escopo atual) e erros. visitar decide pelo no.op, como um visitor escrito à mão; tipoDe calcula o tipo em pós-ordem.
  • Regras desta linguagem: nome declarado antes do uso; nada de declarar duas vezes no mesmo bloco; bloco interno pode sombrear; + só entre tipos iguais; a variável recebe o tipo dela. Sem conversão automática, como na Alguma do Lucrédio e no lab10 do Judson.
  • O lexico é só um apoio para escrever os testes em texto; nos exemplos do professor a lista de tokens vem escrita à mão. Código autoral, testado com Python 3.13.
'''
Mini-bloco: a gramática da dinâmica de 12/11 crescida com declarações, tipos e blocos aninhados.

<programa>     ::= <bloco>
<bloco>        ::= ABREBLOCO <lista_cmd> FECHABLOCO
<lista_cmd>    ::= <cmd> <lista_cmd> | ε
<cmd>          ::= <decl> | <atribuicao> | <bloco>
<decl>         ::= TIPO ID SEMICOLON
<atribuicao>   ::= ID ASSIGN <expr> SEMICOLON
<expr>         ::= <fator> <mais_fatores>
<mais_fatores> ::= MAIS <fator> <mais_fatores> | ε
<fator>        ::= ID | INT | REAL
'''
import re


# ---------- Token e nós: os mesmos do exemplo do robô (ex_sintatico_arvore_desafio.py) ----------
class Token:
    def __init__(self, tipo, valor, linha):
        self.tipo = tipo
        self.valor = valor
        self.linha = linha

    def __repr__(self):
        return f'Token({self.tipo!r}, {self.valor!r}, {self.linha})'


class NoInterno:
    def __init__(self, op, **kwargs):
        self.op = op
        self.d = {}
        for k, v in kwargs.items():
            self.d[k] = v

    def get(self, k):
        return self.d.get(k)

    def __repr__(self):
        atributos = ", ".join(f"{k}={repr(v)}" for k, v in self.d.items())
        return f'NoInterno(op="{self.op}", {atributos})'


class NoFolha:
    def __init__(self, op, valor, linha):
        self.op = op
        self.valor = valor
        self.linha = linha

    def __repr__(self):
        return f'NoFolha(op="{self.op}", valor="{self.valor}", linha={self.linha})'


# ---------- Léxico de apoio: só para não escrever a lista de tokens à mão ----------
PADROES = [
    ('REAL', r'\d+\.\d+'), ('INT', r'\d+'), ('TIPO', r'\b(?:int|real)\b'), ('ID', r'[A-Za-z_]\w*'),
    ('ABREBLOCO', r'\{'), ('FECHABLOCO', r'\}'), ('ASSIGN', r'='), ('MAIS', r'\+'), ('SEMICOLON', r';'),
    ('COMENTARIO', r'//[^\n]*'), ('ESPACO', r'[ \t]+'), ('LINHA', r'\n'),
]
REGEX = re.compile('|'.join(f'(?P<{t}>{p})' for t, p in PADROES))


def lexico(codigo):
    tokens, linha = [], 1
    for m in REGEX.finditer(codigo):
        tipo = m.lastgroup
        if tipo == 'LINHA':
            linha += 1
        elif tipo not in ('ESPACO', 'COMENTARIO'):
            tokens.append(Token(tipo, m.group(), linha))
    tokens.append(Token('EOF', 'EOF', linha))
    return tokens


# ---------- Sintático: a classe do professor, devolvendo a AST ----------
class AnalisadorSintatico:
    def __init__(self, tokens):
        self.tokens = tokens
        self.tokenCorrente = None
        self.posicao = -1
        self.proximoToken()

    def proximoToken(self):
        if self.posicao <= len(self.tokens) - 2:
            self.posicao += 1
            self.tokenCorrente = self.tokens[self.posicao]
        else:
            self.tokenCorrente = None

    def comparar(self, tipoEsperado):
        if self.tokenCorrente is not None and self.tokenCorrente.tipo == tipoEsperado:
            token_consumido = self.tokenCorrente
            self.proximoToken()
            return token_consumido
        tipo_atual = self.tokenCorrente.tipo if self.tokenCorrente else "None"
        raise Exception(f"Erro sintático: esperava '{tipoEsperado}', mas obtive '{tipo_atual}'")

    def analisar(self):
        arvore = self.bloco()
        self.comparar('EOF')
        return arvore

    # <bloco> ::= ABREBLOCO <lista_cmd> FECHABLOCO
    def bloco(self):
        abre = self.comparar('ABREBLOCO')
        lista = self.lista_cmd()
        self.comparar('FECHABLOCO')
        return NoInterno('bloco', listaCmd=lista, linha=abre.linha)

    # <lista_cmd> ::= <cmd> <lista_cmd> | ε
    def lista_cmd(self):
        if self.tokenCorrente is not None and self.tokenCorrente.tipo in ('TIPO', 'ID', 'ABREBLOCO'):
            cmd = self.cmd()
            prox = self.lista_cmd()
            return NoInterno('listaCmd', cmd=cmd, prox=prox)
        return None                                   # ε: o fim da lista é None

    # <cmd> ::= <decl> | <atribuicao> | <bloco>
    def cmd(self):
        if self.tokenCorrente.tipo == 'TIPO':
            return self.decl()
        if self.tokenCorrente.tipo == 'ID':
            return self.atribuicao()
        return self.bloco()

    # <decl> ::= TIPO ID SEMICOLON
    def decl(self):
        tipo = self.comparar('TIPO')
        nome = self.comparar('ID')
        self.comparar('SEMICOLON')
        return NoInterno('decl', tipo=NoFolha('tipo', tipo.valor, tipo.linha),
                         nome=NoFolha('id', nome.valor, nome.linha))

    # <atribuicao> ::= ID ASSIGN <expr> SEMICOLON
    def atribuicao(self):
        nome = self.comparar('ID')
        self.comparar('ASSIGN')
        expr = self.expr()
        self.comparar('SEMICOLON')
        return NoInterno('atribuicao', nome=NoFolha('id', nome.valor, nome.linha), expr=expr)

    # <expr> ::= <fator> <mais_fatores>
    def expr(self):
        esquerda = self.fator()
        return self.mais_fatores(esquerda)           # atributo herdado: a árvore até aqui

    # <mais_fatores> ::= MAIS <fator> <mais_fatores> | ε
    def mais_fatores(self, herdado):
        if self.tokenCorrente is not None and self.tokenCorrente.tipo == 'MAIS':
            mais = self.comparar('MAIS')
            direita = self.fator()
            novo = NoInterno('soma', esq=herdado, dir=direita, linha=mais.linha)
            return self.mais_fatores(novo)           # passa a árvore maior para baixo
        return herdado                                # ε: o herdado vira o sintetizado

    # <fator> ::= ID | INT | REAL
    def fator(self):
        if self.tokenCorrente is not None and self.tokenCorrente.tipo == 'ID':
            t = self.comparar('ID')
            return NoFolha('id', t.valor, t.linha)
        if self.tokenCorrente is not None and self.tokenCorrente.tipo == 'INT':
            t = self.comparar('INT')
            return NoFolha('int', t.valor, t.linha)
        t = self.comparar('REAL')
        return NoFolha('real', t.valor, t.linha)


# ---------- Semântico: anda na AST com uma pilha de tabelas de símbolos ----------
class AnalisadorSemantico:
    def __init__(self):
        self.escopos = []          # pilha de tabelas: escopos[-1] é o escopo atual
        self.erros = []            # não para no primeiro erro: junta todos

    def erro(self, linha, mensagem):
        self.erros.append(f"Erro semântico na linha {linha}: {mensagem}")

    # --- tabela de símbolos ---
    def criarEscopo(self):
        self.escopos.append({})

    def abandonarEscopo(self):
        self.escopos.pop()         # remove a tabela inteira, nunca um símbolo solto

    def declarar(self, nome, tipo, linha):
        atual = self.escopos[-1]
        if nome in atual:
            self.erro(linha, f"'{nome}' já foi declarada neste bloco")
        else:
            atual[nome] = tipo

    def buscar(self, nome):
        for tabela in reversed(self.escopos):       # do topo para o fundo
            if nome in tabela:
                return tabela[nome]
        return None

    # --- percurso ---
    def analisar(self, arvore):
        self.visitar(arvore)
        return self.erros

    def visitar(self, no):
        if no is None:
            return
        if no.op == 'bloco':
            self.criarEscopo()
            self.visitar(no.get('listaCmd'))
            self.abandonarEscopo()
        elif no.op == 'listaCmd':
            self.visitar(no.get('cmd'))
            self.visitar(no.get('prox'))
        elif no.op == 'decl':
            nome = no.get('nome')
            self.declarar(nome.valor, no.get('tipo').valor, nome.linha)
        elif no.op == 'atribuicao':
            self.atribuicao(no)

    def atribuicao(self, no):
        nome = no.get('nome')
        tipo_var = self.buscar(nome.valor)
        tipo_expr = self.tipoDe(no.get('expr'))
        if tipo_var is None:
            self.erro(nome.linha, f"'{nome.valor}' não foi declarada")
        elif tipo_expr != 'invalido' and tipo_var != tipo_expr:
            self.erro(nome.linha, f"'{nome.valor}' é {tipo_var} e recebe uma expressão {tipo_expr}")

    def tipoDe(self, no):
        if no.op == 'int':
            return 'int'
        if no.op == 'real':
            return 'real'
        if no.op == 'id':
            tipo = self.buscar(no.valor)
            if tipo is None:
                self.erro(no.linha, f"'{no.valor}' não foi declarada")
                return 'invalido'
            return tipo
        # soma: pós-ordem, primeiro os filhos
        esq = self.tipoDe(no.get('esq'))
        dir = self.tipoDe(no.get('dir'))
        if 'invalido' in (esq, dir):
            return 'invalido'                         # o erro já foi contado lá embaixo
        if esq != dir:
            self.erro(no.get('linha'), f"'+' entre {esq} e {dir}")
            return 'invalido'
        return esq


def compilar(codigo):
    arvore = AnalisadorSintatico(lexico(codigo)).analisar()
    return arvore, AnalisadorSemantico().analisar(arvore)

O que sobra para o semântico

Duas fases dizem sim; a terceira diz não.

O sintático só confere a forma. O semântico confere as regras que dependem de lembrar nomes e tipos, que uma gramática livre de contexto não consegue guardar.

  • Dois programas que passam no léxico e no sintático e estão errados: x = "oi"; com x inteiro (a regra é "variável = expressão", e um literal é uma expressão) e total = 1; sem total declarado.
  • Amarrar o uso de um nome à sua declaração é sensível ao contexto (aula 01). O sintático ignora isso de propósito, para continuar sendo um autômato com pilha simples; o resto vem depois, com a tabela de símbolos.
  • O que o semântico faz: coleta os tipos das variáveis e dos parâmetros, verifica e às vezes converte tipos, e liga cada nome ao seu significado. As fases estão na aula 07; o que nenhuma gramática resolve, na mesma aula.
  • Ada repete o nome do subprograma no fim: procedure xpto is … end xpto;. Conferir que os dois nomes são iguais é comparar com o nome guardado na tabela, sem gramática sensível ao contexto.
  • Esse conjunto de regras se chama semântica estática: o significado conferido sem rodar o programa.
  • Quebrar uma delas é um erro semântico. Parte dos livros e o Judson chamam os mesmos erros de erros de sintaxe, porque ferem regras da linguagem que a gramática não escreve. A nomenclatura é misturada.
  • Não existe um BNF da semântica. Como cada linguagem pede verificações diferentes, não há gerador automático como para o sintático: o semântico é escrito à mão, quase sempre em volta da tabela de símbolos.
  • Erro semântico do compilador não é erro de lógica. Escrever horas = dias * 60 no lugar de * 24 compila sem aviso: nenhuma fase sabe o que você quis dizer.
  • O semântico só roda em programa sintaticamente certo. Se o parser recusou, não existe árvore para ele andar.

Decidido na compilação ou só na execução

Do lado azul, o código basta; do âmbar, só rodando.

A verificação estática é feita em tempo de compilação, só com o que está escrito no código. O que depende de um valor que só existe com o programa rodando fica para o tempo de execução.

  • Dá para decidir na compilação: o tipo e o escopo de cada variável (as declarações e as chaves dizem); o endereço das variáveis globais e dos membros estáticos de classe, de forma relativa (a primeira no 0, a seguinte 4 bytes depois), que o loader transforma em endereço real ao carregar; o valor de uma expressão só com constantes.
  • Só na execução: o endereço de um objeto criado com new (o compilador nem sabe se aquele new roda, se está dentro de um if), e o resultado de 10 + rand() ou de 10 + x com x digitado.
  • Calcular 10 + 5 na compilação é a dobra de constantes. No godbolt.org, int x = 10 + 5; vira um mov de 15 no assembly, sem instrução de soma.
  • As verificações estáticas do semântico são de dois tipos: as regras de sintaxe que a gramática não escreve (nome declarado, um nome por escopo, break dentro de laço) e a verificação de tipos.
  • Algumas cabem durante a construção da árvore (o Judson as põe nos construtores dos nós); outras precisam olhar pedaços grandes da árvore pronta.
const int x = 10 + 10;          // o compilador pode trocar por 20
const int y = 10 + rand();      // constante válida: calculada ao rodar, depois não muda
constexpr int z = 10 + rand();  // erro: rand não é constexpr, não roda em compilação
// g++ -std=c++17 constexpr.cpp -o constexpr
  • const diz "não muda depois de pronto", não "conhecido na compilação". Quem exige o valor em compilação é o constexpr.
  • Endereço de global "conhecido na compilação" é relativo. O absoluto só aparece quando o loader põe o programa na memória.

Atributos: o valor que sobe e o valor que desce

em loop34: o 3 desce como herdado, soma com o 4 e volta como sintetizado.

Uma gramática de atributos pendura valores nos símbolos e diz, em cada regra, como calculá-los. O atributo sintetizado sobe dos filhos para o pai; o atributo herdado desce do pai, ou de um irmão à esquerda, para o filho.

  • Exemplo: somar os dígitos de um número. 123 dá 6 e 34 dá 7. Com a gramática que lê da esquerda para a direita e recursão à esquerda, tudo é sintetizado:
N → N₁ num { N.v = N₁.v + num.v } N → num { N.v = num.v }
  • N.v é o atributo v do nó N. N₁ é o mesmo N; o índice só separa as duas ocorrências na regra.
  • num.v é o valor do dígito, que chega pronto do léxico: um atributo intrínseco, sempre numa folha.
  • Na análise descendente a recursão à esquerda trava (aula 11). Sem ela, o valor de baixo ainda não existe quando você desce, e a conta precisa ir descendo: aparece o herdado (.h), que no fim vira sintetizado (.s).
N → num { X.h = num.v } X { N.v = X.s } X → num { X₁.h = X.h + num.v } X₁ { X.s = X₁.s } X → ε { X.s = X.h }
  • Leia: desça somando no herdado até o ε; no ε, o herdado vira sintetizado; suba copiando até N. A Figura 1 faz as duas versões com 34.
  • Na descida recursiva, sintetizado é o valor de retorno e herdado é um parâmetro. A função X recebe o herdado e devolve o sintetizado:
# Soma dos dígitos, L-atribuída:  N → num X ;  X → num X₁ | ε
class SomaDigitos(AnalisadorSintatico):
    def analisar(self):
        v = self.N()
        self.comparar('EOF')
        return v

    def N(self):
        v = int(self.comparar('NUM').valor)    # num.v: atributo intrínseco
        return self.X(v)                       # X.h = num.v   e   N.v = X.s

    def X(self, h):                            # h: o atributo herdado de X
        if self.tokenCorrente.tipo == 'NUM':
            v = int(self.comparar('NUM').valor)
            return self.X(h + v)               # X₁.h = X.h + num.v   e   X.s = X₁.s
        return h                               # X → ε:   X.s = X.h
  • Regra geral: numa produção Y → X₁ X₂ … Xₙ, um atributo de Y é uma função de alguns atributos dos Xᵢ. O que não se calcula, se confere: um predicado é uma função booleana na regra, por exemplo "o tipo desta soma é inteiro", que dá falso se há um real no meio.
  • Em mais_fatores(herdado) da Mini-bloco o herdado é a árvore à esquerda, e não um número: a mesma técnica monta a AST associativa à esquerda.
  • Herdado não vem só do pai. Em X₁.h = X.h + num.v, o num.v é de um irmão à esquerda.
  • Esquecer X.s = X.h no ε deixa a conta sem resultado: o valor desceu inteiro e não tem por onde voltar.

Onde as contas ficam: SDD, SDT, S e L-atribuído

A direção das setas decide qual análise consegue fazer as contas.

Uma definição dirigida pela sintaxe põe as contas ao lado de cada regra, sem dizer quando rodam. A tradução dirigida pela sintaxe (SDT) põe as ações semânticas dentro do corpo da regra, na posição em que devem rodar, e o analisador as executa ao passar por ali.

  • SDD serve de especificação para quem escreve o compilador à mão. SDT é o formato dos geradores (ANTLR, JavaCC, yacc), que copiam as ações para o analisador gerado; por isso o Lucrédio foca nele.
  • A ordem importa: na descida, um sintetizado não sai antes do herdado de que depende. Dois esquemas garantem uma ordem que funciona:
  • S-atribuído: só sintetizados, ações sempre no fim da regra. Combina com a análise ascendente (aula 11), que monta de baixo para cima.
  • L-atribuído: herdados que dependem só do pai e dos irmãos à esquerda, ações no meio e no fim. Dá para fazer tudo lendo da esquerda para a direita, por isso combina com a descendente. O curso da UNIVESP usa JavaCC, logo L-atribuído.
  • Fora desses dois, a ordem das contas sai de um grafo de dependências: uma seta de cada atributo para os que dependem dele.
A → A₁ Y { A.a = g(A₁.a, Y.y) } | X { A.a = f(X.x) } ⇓ sem recursão à esquerda A → X { R.h = f(X.x) } R { A.a = R.s } R → Y { R₁.h = g(R.h, Y.y) } R₁ { R.s = R₁.s } R → ε { R.s = R.h }
  • A receita geral: o que era sintetizado no A da esquerda vira herdado do R seguinte. É a mesma conta dos dígitos, com f e g quaisquer.
  • A calculadora do Lucrédio (projeto 1, em ANTLR com returns [int val] e termo2[$fator.val]), escrita em Python na classe da aula. 2 + 3 * 4 dá 14, (2 + 3) * 4 dá 20 e 10 - 3 - 2 dá 5:
class Calculadora(AnalisadorSintatico):
    def analisar(self):
        v = self.expressao()
        self.comparar('EOF')
        return v

    # <expressao> ::= <termo> <expressao2>
    def expressao(self):
        return self.expressao2(self.termo())

    # <expressao2> ::= MAIS <termo> <expressao2> | MENOS <termo> <expressao2> | ε
    def expressao2(self, herdado):
        if self.tokenCorrente.tipo == 'MAIS':
            self.comparar('MAIS')
            return self.expressao2(herdado + self.termo())
        if self.tokenCorrente.tipo == 'MENOS':
            self.comparar('MENOS')
            return self.expressao2(herdado - self.termo())   # o de antes menos o termo
        return herdado

    # <termo> ::= <fator> <termo2>
    def termo(self):
        return self.termo2(self.fator())

    # <termo2> ::= VEZES <fator> <termo2> | ε
    def termo2(self, herdado):
        if self.tokenCorrente.tipo == 'VEZES':
            self.comparar('VEZES')
            return self.termo2(herdado * self.fator())
        return herdado

    # <fator> ::= ABREPAR <expressao> FECHAPAR | NUM
    def fator(self):
        if self.tokenCorrente.tipo == 'ABREPAR':
            self.comparar('ABREPAR')
            v = self.expressao()
            self.comparar('FECHAPAR')
            return v
        return int(self.comparar('NUM').valor)
  • No ANTLR a mesma regra fica termo2[int herdado] returns [int val] : '*' fator t=termo2[$herdado * $fator.val] { $val = $t.val; } | { $val = $herdado; } ;. O argumento entre colchetes é o herdado; o returns, o sintetizado.
  • A crítica do próprio Lucrédio: tirar a recursão à esquerda espalhou uma expressão por quatro regras e obrigou a passar valores para cima e para baixo. Com o * do ANTLR, ou com um while, a conta fica num laço só (aula 12).
  • Para montar árvore em vez de valor, troque a conta por um nó: E.ptr = geraNo('+', E₁.ptr, T.ptr) e F.ptr = geraFolha(num) na versão ascendente; na descendente, R₁.h = geraNo(op, R.h, T.ptr). A função R(h) da UNIVESP recebe um ponteiro para nó e devolve outro: é o mais_fatores da Mini-bloco.
  • Calcular herdado * fator dentro do termo2 e jogar fora o que a chamada recursiva devolve: 2 * 3 * 4 * 5 dá 6, porque só o primeiro par entra na conta. O produto parcial tem de descer.
  • Na subtração, herdado - termo. Com termo - herdado, 10 - 3 - 2 vira (3 − 10) e depois 2 − (−7) = 9.

Que nós a árvore ganha

while …; if …; vira Seq(While, Seq(If, nulo)).

Cada construção vira um nó, e as partes que importam viram filhos: If(cond, cmd), While(cond, cmd), Assign(lugar, expr). Pontuação, parênteses e declarações ficam fora. A AST em si está na aula 09 e a montagem na descida, na aula 12.

  • O esquema do Judson monta a árvore com ações: stmt → if ( expr ) stmt₁ { stmt.n = new If(expr.n, stmt₁.n) }. Todo não terminal tem um atributo n, o seu nó.
  • Comando sem palavra-chave ganha um nome que diz o que ele faz: stmt → expr ; vira Eval(expr.n).
  • Lista de comandos vira o nó Seq: stmts → stmt stmts₁ { new Seq(stmt.n, stmts₁.n) } | ε { nulo }. A informação fica sempre de um lado; do outro, outro Seq ou nulo. Na Mini-bloco é o listaCmd(cmd, prox).
  • factor → ( expr ) { factor.n = expr.n }: os parênteses não criam nó. A forma da árvore já guarda a precedência; 9 - 5 + 2 vira +(−(9, 5), 2).
  • Declarações não viram nó no compilador do Judson: elas vão direto para a tabela de símbolos durante a análise. Na Mini-bloco, decl vira nó porque quem preenche a tabela é o semântico, numa passada separada.
  • A ordem dos filhos é uma combinação: escolha uma e use a mesma ao percorrer. No DoWhile(stmt, expr) do Judson o comando vem primeiro, como no texto.
  • Classes: Node com duas filhas, Expression (guarda o tipo e o token, para a mensagem de erro) e Statement. Constant, Identifier, Logical, Relational, Arithmetic e o unário são expressões; Seq, Assign, If, While, DoWhile, comandos.
  • Operadores com as mesmas regras de tipo e de geração de código dividem um nó, e a árvore fica com menos tipos de nó:

  • O Judson chama a AST de "árvore sintática" e a árvore com todos os símbolos de "árvore de derivação". Em outros materiais, árvore sintática é a de derivação. Confira de qual o texto fala pela presença dos parênteses e do ;.

Durante a análise ou numa passada depois

Com a árvore pronta, o visitor anda nela quantas vezes quiser.

As verificações podem rodar dentro do sintático, como ações nas regras, ou depois, numa passada que percorre a árvore pronta. A segunda forma é o visitor: uma classe com um método por tipo de nó.

  • Ações na gramática: o projeto 1 do Lucrédio, e o Judson pondo as conferências nos construtores dos nós (Logical recusa operandos que não são booleanos na hora em que é criado).
  • Visitor no ANTLR: ligue a opção visitor no plugin do pom.xml e o ANTLR gera a interface …Visitor e a classe …BaseVisitor, com um visitX por regra. No BaseVisitor cada método só faz visitChildren(ctx): anda pela árvore sem fazer nada.
  • Você estende o BaseVisitor e sobrescreve só o que interessa: class Calculador extends ExpressoesBaseVisitor<Integer>. O tipo entre < > é o retorno de todos os métodos.
  • Com a árvore pronta, um método "estica o braço" até os filhos: visitExpressao pega ctx.termo1, percorre ctx.outrosTermos num for e lê o operador com ctx.op1(i).getText(). Rótulos na gramática dão os nomes: termo1=termo para um, outrosTermos+=termo para a lista.
  • Alternativas se descobrem pelo filho que não é nulo: if (ctx.NUM() != null) é número, senão é expressão entre parênteses.
  • Custo: uma passada a mais sobre a árvore, quase nada fora de árvores gigantes. Ganho: gramática limpa, e vários visitors no mesmo compilador (um para tipos, um para calcular, um para gerar código). O Lucrédio recomenda visitor; ação na gramática só para coisa muito simples.
  • O Thain faz duas passadas: primeiro resolve os nomes (decl_resolve, expr_resolve), depois confere os tipos (expr_typecheck). Na Mini-bloco, visitar faz as duas coisas numa passada só.
  • Implementar a interface …Visitor obriga a escrever todos os métodos. Estender o …BaseVisitor deixa escolher.
  • Sem rótulos, termo (op1 termo)* gera uma lista só de termos, e o primeiro é o índice 0. Com termo1= e outrosTermos+=, cada um tem nome.

O que a tabela de símbolos guarda

Cada linha é um nome; cada coluna, algo que o compilador lembra.

A tabela de símbolos guarda, para cada nome do programa, o que o compilador precisa lembrar dele: a categoria do símbolo (variável, constante, procedimento), o tipo, o valor e o que mais a linguagem pedir.

  • Vetor precisa do tamanho e dos limites. Função precisa da lista de parâmetros com tipos e do tipo de retorno. Procedimento não tem tipo nem valor: na tabela única, essas colunas ficam vazias.
  • O Thain guarda em cada símbolo: kind (LOCAL, PARAM ou GLOBAL), type, name e which (a posição entre os locais ou parâmetros, usada depois para achar o lugar na memória).
  • Três operações. Inserir: na declaração, depois de conferir que o nome não existe no escopo atual. Verificar (buscar): em cada uso. Remover: quando o nome deixa de valer, no fim do bloco ou da função.
  • Questões de projeto: a tabela é consultada a compilação inteira, então precisa ser rápida. Estática (vetor de tamanho fixo) ou dinâmica (cresce); hoje dá para usar dinâmica sem medo. Tamanho típico: de centenas a milhares de linhas.
  • Estrutura: lista (busca sequencial, uma posição por vez), árvore de busca (busca binária) ou tabela hash, que leva o nome direto à posição. O dict do Python e o HashMap do Java são hash.
  • Uma tabela para tudo (com colunas vazias) ou uma por categoria; uma tabela para o programa ou uma por escopo. Linguagem de um nível só, como COBOL e Fortran antigos, se vira com uma lista linear. Com blocos aninhados (Algol, Pascal, C, Java), uma tabela por escopo é o jeito natural (pilha de tabelas).
  • No HashMap do Java, get de um nome que não existe devolve null, sem erro. No dict do Python, tabela[nome] lança KeyError; use nome in tabela ou tabela.get(nome).

Escopo: qual declaração vale aqui

Cada caixa é um escopo; o print procura de dentro para fora.

Escopo é o trecho em que uma declaração vale. No escopo estático, o que a maioria das linguagens usa, isso se decide pelo texto: basta olhar as chaves, sem rodar o programa.

  • Nomes iguais em escopos diferentes são coisas diferentes, e o compilador precisa saber qual vale em cada uso. Duas regras resolvem:
  • Declaração antes do uso: o nome tem de estar declarado no escopo atual ou num escopo de fora.
  • Aninhamento mais próximo: com vários iguais visíveis, vale o do escopo mais interno.
  • No desenho, o print do meio enxerga a = 3 (o mais interno) e b = 2 (o do bloco do meio): imprime 3 2. Ao sair de cada bloco, a declaração de fora volta a valer.
  • A declaração interna faz sombreamento da externa, que continua existindo. Consequência para a tabela: inserir oculta a anterior sem sobrescrever; buscar acha a mais interna; remover tira só a interna e restaura a oculta.
  • O Thain declara x três vezes: global inteiro valendo 10, parâmetro string de f e booleano num bloco dentro de f. main imprime x e chama f("hello"), que imprime o parâmetro e depois o do bloco: sai 10 hello false.
  • Visibilidade com procedimentos (UNIVESP): globais a e b, procedimentos p e q, e r declarado dentro de q. O corpo do programa vê a, b, p e q, mas não r. Dentro de r se vê tudo o que é global e o próprio r, que pode chamar a si mesmo.
  • Pascal tem sub-rotinas aninhadas (g e h dentro de f, dentro do programa), e o j local de g pode ter o mesmo nome do j do programa. C aninha blocos com chaves.
  • Redeclarar no mesmo bloco é erro; num bloco interno é sombreamento. Na Mini-bloco, { int a; int a; } dá erro e { int a; { real a; } } não.
  • Depois do bloco interno, o nome interno some: { { int t; } t = 1; } dá "'t' não foi declarada".

Pilha de tabelas: um dict por bloco

em loopEntra no bloco: empilha. Sai: desempilha a tabela inteira.

A pilha de tabelas implementa o escopo estático: uma tabela por escopo, empilhada ao entrar no bloco e desempilhada ao sair. Declarar mexe só no topo; buscar vai do topo para o fundo e para na primeira que tem o nome.

  • Nunca se remove um símbolo solto: quando o escopo acaba, sai a tabela inteira. A remoção com restauração vem de graça, porque a tabela de baixo nunca foi tocada.

  • No Thain, cada tabela é hash; existe o escopo global, o dos parâmetros e locais de cada função e um a cada par de chaves. scope_level() > 1 diz se uma declaração é local ou global.
  • No Judson, Block() cria uma tabela nova ao entrar e restaura a anterior ao sair, e Local() procura o nome: não achou, "variável não declarada"; achou, o símbolo traz o tipo.

  • Declarar olha só o topo; usar olha a pilha toda. Buscar a pilha toda ao declarar proíbe o sombreamento; buscar só o topo ao usar não acha as globais.
  • Desempilhar antes de usar o valor do bloco perde as declarações dele. No let, primeiro calcula a expressão do in, depois abandona o escopo.

Exemplo: let … in com escopos aninhados

O let declara, o in calcula.

A linguagem de cálculo do Lucrédio declara variáveis com let e usa depois do in. Cada let abre um escopo novo, e o resultado do programa é o valor da expressão.

  • Gramática (ANTLR): expressao : termo1=termo ('+' outrosTermos+=termo)* ;, termo : '(' expressao ')' | VAR | NUM | 'let' listaDecls 'in' expressao ;, listaDecls : decl (',' decl)* ;, decl : nome=VAR '=' expressao ;. Só soma.
  • Regra 1: nada de dois nomes iguais na mesma lista de declarações.
  • Regra 2: usar um nome não declarado é erro; ele precisa estar no escopo atual ou num de fora.
  • Regra 3: o escopo de cada declaração vai até o fim do corpo, com aninhamento mais próximo.
  • Regra 4: a lista é sequencial. Cada declaração já vale para a próxima da mesma lista; a que está sendo calculada ainda não vale.
  • O visitor Calculador (retorno Double) faz, no let: criarNovoEscopo(), visita as declarações (cada uma insere no topo), calcula a subexpressão do in, abandonarEscopo() e devolve o valor. Numa variável, percorre os escopos do topo ao fundo e devolve o valor da primeira que tem o nome.
let x = 2, y = 3 in
  let x = x + 1,
      y = let z = 3, x = 4 in x + y + z
  in x + y                              -- vale 13
  • O x de x + 1 é o de fora (2): o novo x vale 3.
  • No let mais interno, x + y + z = 4 + 3 + 3 = 10. O x é o 4 (mais interno); o y é o 3 de fora, porque o y que está sendo declarado ainda não existe.
  • Esse 10 vira o y do meio, e x + y = 3 + 10 = 13. A Figura 2 mostra a pilha em cada passo.
  • let x = 2, x = 3 in x + 1 dá "x declarada duas vezes no mesmo escopo". Usar y só com x declarado dá "y não foi declarado antes do uso".
  • Achar 15 no exercício é usar o y do meio dentro do let interno. Ele só existe depois que a sua expressão termina.

Sistema de tipos: para que serve e como se classifica

Três eixos independentes.

O sistema de tipos dá a quem programa um jeito de fazer afirmações ("isto é inteiro") que o compilador confere sozinho. Para descrevê-lo, a linguagem diz quais tipos existem, como se combinam e o que acontece quando tipos diferentes se encontram.

  • Para que serve: correção (atribuir inteiro a ponteiro é quase certamente erro); desempenho (o compilador escolhe a instrução: a+b vira ADDL para inteiros e FADD para reais no x86); expressividade (o print do B-Minor não precisa saber o tipo, ele é deduzido).
  • Segura ou insegura. Numa linguagem segura, nenhum programa quebra as estruturas da linguagem: em C#, a[i] com i até 100 num vetor de 10 lança IndexOutOfRangeException. Em C, que é insegura, o mesmo laço escreve por cima de qualquer coisa.
  • Estática ou dinâmica. Na tipagem estática, tudo é conferido na compilação e o código final nem guarda os tipos. Na tipagem dinâmica, o tipo fica junto do valor na memória e cada operação confere ao rodar; dá até para perguntar o tipo, como o instanceof do Java.
  • Explícita ou implícita (tipagem explícita e implícita). Em C você escreve o tipo, e int x = 32.5; deveria gerar aviso; em C++11, auto x = 32.5; deduz double.
  • Tipo atômico: inteiro, real, booleano, caractere; a linguagem precisa dizer a faixa (8, 16, 32 ou 64 bits; ASCII ou Unicode). Tipos do usuário restringem um atômico: em Ada, type Month is range 1..12; recusa 13 e não mistura com Day. O typedef de C só dá outro nome, e Day d = m; passa.
  • Enumeração (enum Fuzzy { True, False, Uncertain } em Rust) é um inteiro por dentro, mas o compilador impede valor ilegal; em C, enum e int se misturam.
  • Tipo composto: struct (latitude e longitude juntas), union (em C, n.i e n.f ocupam a mesma memória: gravar 10 em n.i e ler n.f dá lixo), tipo variante (o enum Expression do Rust, com ADD, MULTIPLY, INTEGER e NAME, só deixa usar os campos do caso certo), vetor e função.
  • O B-Minor do Thain é seguro, estático e explícito. Regras: valor só vai para variável do mesmo tipo, argumento só para parâmetro do mesmo tipo, return com o tipo da função, operador binário com o mesmo tipo dos dois lados; == != em qualquer tipo menos void, vetor e função; < <= >= > só em inteiros; ! && || só em booleanos; aritméticos só em inteiros. Comparações e lógicos devolvem boolean.
  • Os três eixos são independentes. Java é estática e segura; C é estática e insegura; Python é dinâmica e segura.
  • Union e variante parecem iguais. A union deixa ler o campo errado; a variante não.

Verificação de tipos na árvore

As folhas dão o tipo; cada operador decide o seu.

A verificação de tipos calcula o tipo de cada expressão a partir das folhas e confere se cada operador, atribuição, condição e chamada recebe os tipos que aceita.

  • Onde se confere: atribuição (o lado esquerdo aceita o tipo do direito), condição de if e while (booleana, ou conversível), operandos de cada operador, argumentos de cada chamada.
  • Por que tanto cuidado: o processador não tem instrução que mistura tipos. Soma é de dois inteiros ou de dois reais; misturar exige que a linguagem converta antes.
  • Em pós-ordem, como o expr_typecheck do Thain: primeiro os filhos, depois o nó. Folha literal tem o tipo do literal; folha de nome tem o tipo da tabela. Nó interno compara os filhos com as regras e devolve o tipo do operador.
  • O tipo nasce em dois lugares. No léxico: o Judson devolve token real quando o número tem ponto, e 9.2 vira constante float. Na tabela: o símbolo guarda o tipo da declaração, e o identificador recebe esse tipo.
  • A ação do Judson para E → E₁ <= E₂: if (E₁.type == E₂.type) E.type = boolean; else error;. No lab10, os construtores conferem: Logical quer dois bool, Relational e Arithmetic querem tipos iguais, Assign quer variável e expressão do mesmo tipo.
  • Na Alguma do Lucrédio, o enum TipoAlguma tem INTEIRO, REAL e INVALIDO, e há um verificarTipo para expressão, termo, fator e nome. Na expressão, o primeiro termo dá o tipo; um termo diferente gera "Expressão … contém tipos incompatíveis" com linha e coluna do primeiro token (ctx.start) e marca a expressão como tipo inválido.
  • O inválido evita erros em cascata: quem recebe um inválido não reclama de novo. O Thain diz o mesmo de outro jeito: depois do erro, devolva um tipo válido para continuar e achar o maior número de erros.
  • Conferir no termo e na expressão deixa a mensagem mais precisa: em 2 + 3 * x com x real, o erro aponta o termo 3*x.
  • Mensagem boa diz os tipos e as expressões. Em vez de "incompatibilidade de tipos na expressão", o Thain imprime "não dá para comparar um boolean (b) com um integer (5)" e depois "não dá para somar um boolean (b<5) com uma string (s)".
  • Sem o inválido, a + b + 1 daria duas mensagens: uma para a + b e outra para o resultado somado com 1, que não tem erro próprio.
  • Expressão inválida não se compara com a variável. O visitComandoAtribuicao do Lucrédio só confere o tipo da variável se o da expressão não é INVALIDO.

Tipos diferentes juntos: proibir, converter ou sobrecarregar

A coerção vira um nó a mais, colocado pelo verificador.

Quando dois tipos diferentes se encontram, a linguagem escolhe uma saída: recusar, copiar os bits, converter para um valor equivalente ou reinterpretar o valor.

  • Recusar: o B-Minor dá erro e, se você quer mesmo, chama uma função como IntToFloat. É o que a Mini-bloco faz.
  • Copiar os bits: raro e perigoso, nada garante que os bits façam sentido no outro tipo. Acontece entre tipos de ponteiro em C.
  • Converter: inteiro e real, com sinal e sem sinal. É a coerção: em 2 * 3.14, o 2 vira 2.0. O verificador põe um nó de conversão na árvore, e a geração de código vê a conversão como qualquer outro nó.
  • Reinterpretar: em Perl, $b = @days; guarda em b o tamanho da lista, não a lista.
  • Na chamada: com p(int a, real b), p(10, 22) passa, porque 22 vira real sem perder nada.
  • Flexibilizar o <= do Judson: em vez de exigir tipos iguais, aceitar se E₁ converte para o tipo de E₂ ou o contrário, converter e comparar.
  • Sobrecarga: o significado do operador sai dos tipos dos operandos. + soma dois números e concatena duas strings; string com número só se o número converter para string.
  • A Mini-bloco com coerção de int para real (exercício no estilo da atividade do Judson, solução autoral). Em r = i + 2.5; o i ganha um nó int_para_real; r = 3; também passa; i = r + 1; continua erro, porque real em int perde a parte decimal:
class SemanticoComConversao(AnalisadorSemantico):
    def converter(self, no):
        return NoInterno('int_para_real', expr=no)

    def tipoDe(self, no):
        if no.op == 'int_para_real':
            return 'real'
        if no.op != 'soma':
            return super().tipoDe(no)
        esq = self.tipoDe(no.get('esq'))
        dir = self.tipoDe(no.get('dir'))
        if 'invalido' in (esq, dir):
            return 'invalido'
        if esq == 'int' and dir == 'real':
            no.d['esq'] = self.converter(no.get('esq'))
            return 'real'
        if esq == 'real' and dir == 'int':
            no.d['dir'] = self.converter(no.get('dir'))
            return 'real'
        return esq

    def atribuicao(self, no):
        nome = no.get('nome')
        tipo_var = self.buscar(nome.valor)
        tipo_expr = self.tipoDe(no.get('expr'))
        if tipo_var is None:
            self.erro(nome.linha, f"'{nome.valor}' não foi declarada")
        elif tipo_var == 'real' and tipo_expr == 'int':
            no.d['expr'] = self.converter(no.get('expr'))      # alarga: não perde nada
        elif tipo_expr != 'invalido' and tipo_var != tipo_expr:
            self.erro(nome.linha, f"'{nome.valor}' é {tipo_var} e recebe uma expressão {tipo_expr}")
  • No mesmo programa, a classe sem conversão dá três erros (linhas 4, 5 e 6); a com conversão dá um, o da linha 6.
  • Conversão automática pode perder informação mesmo "alargando": um float de 32 bits tem 24 bits de mantissa, e 16 777 217 convertido vira 16 777 216.
  • A conversão tem de mudar a árvore. Só devolver real como tipo, sem o nó, deixa a geração de código somar um inteiro com um real.

Valor L e valor R

À esquerda, um lugar; à direita, um valor.

À esquerda do = precisa estar um lugar na memória, um valor L. À direita basta um valor, um valor R.

  • i = 5;: i é valor L (uma variável tem endereço). j = i + 1;: aqui i é usado como valor R, o programa só lê o valor dele.
  • Têm valor L: identificador, posição de vetor (vet[2]), campo de registro. Uma constante como 5 só tem valor R e não pode ficar à esquerda.
  • Em gramáticas com expressões mais livres, o parser aceita um número à esquerda, e quem recusa é o semântico. Na Mini-bloco, a regra ID ASSIGN <expr> já exige um nome à esquerda.
  • Sozinha, uma variável é valor L, porque todo nome está ligado a um bloco de memória. Dentro de uma expressão, ela faz o papel de valor R.
  • C++ separa os dois nas referências: int& recebe valor L e int&& recebe valor R. Com as duas versões de func, func(val) chama a de int& e func(5), a de int&&.
  • vet[i + 1] = 0 é válido: o resultado do acesso é um lugar, mesmo com uma conta dentro dos colchetes.

Outras verificações: chamadas, break, return, vetores

Cada chamada confere número e tipo.

Cada linguagem acrescenta as suas verificações. As mais comuns, além de nomes e tipos de expressão, são as de chamada, de controle e de vetor.

  • Parâmetro formal e argumento concordam em número e em tipo. Para conferir, a tabela guarda, junto do nome da função, a lista dos parâmetros com seus tipos.
  • break só dentro de laço; a gramática não diz isso em lugar nenhum. Um nome por escopo (escopo).
  • return com o tipo de retorno da função (B-Minor). Função void não devolve valor.
  • Acesso a[i]: a precisa ser vetor, i precisa ser inteiro, e o resultado é o tipo dos elementos (o EXPR_DEREF do Thain). Se a não é vetor, o erro sai e um tipo válido volta, para continuar.
  • Índice dentro dos limites quase nunca se confere em compilação: C não confere nunca, C# confere ao rodar.
  • Em C++, declarar variável dentro de um case exige chaves: o switch pode pular direto para outro case e passar por cima da inicialização.
  • Concordar em tipo pode incluir conversão: p(10, 22) passa, mas p(2.5, 1.0) não, porque o 2.5 iria para um int e perderia a parte decimal.

No projeto da nova linguagem

Do papel ao semântico.

No projeto, o semântico recebe a AST do sintático da aula 12 e confere as regras que a especificação da aula 09 descreve em texto e a gramática não expressa.

  • Escreva as regras antes do código: precisa declarar antes de usar? Bloco interno pode sombrear? Que conversões são automáticas? Cada resposta é uma linha do semântico.
  • Se a linguagem tem blocos ou funções, use a pilha de tabelas da Mini-bloco; se tudo é global, uma tabela basta, como na Alguma.
  • Calcule tipos em pós-ordem, com um tipo inválido para não repetir mensagem, e guarde a linha nas folhas para as mensagens.
  • Os exemplos com erro da especificação viram testes: cada um tem de gerar a mensagem certa na linha certa; os válidos, a lista vazia.

Treino: exercícios autorais

Exercícios escritos para treinar com o código desta aula. Não são do professor. Tente antes de abrir a resposta.

1 · Que mensagens a Mini-bloco dá para este programa, todo na linha 1? 
{ real a; int b; b = a;
  { int a; a = b + 1; }
  a = a + 1; }
Uma resposta

Duas. b = a: "'b' é int e recebe uma expressão real". No bloco interno, a é o int, e a = b + 1 passa. Fora, a = a + 1 soma o real de fora com o int 1: "'+' entre real e int".

2 · A atividade do Judson pede conversão automática de int para bool: 0 vira false, qualquer outro valor vira true. Onde ela entra, se a Mini-bloco tivesse um operador lógico e?
Uma resposta

No ramo do nó lógico de tipoDe: calcule o tipo dos dois filhos; o que vier int ganha um nó NoInterno('int_para_bool', expr=filho) no lugar dele, e o nó devolve bool. Real continua erro. É o mesmo molde do SemanticoComConversao, trocando o tipo de destino.

3 · q = r + r; sem r declarado avisa duas vezes. Mude o semântico para avisar uma vez só.
Uma resposta

No ramo id de tipoDe, depois de registrar o erro, faça self.escopos[-1][no.valor] = 'invalido'. O segundo uso acha o nome com tipo inválido e não reclama. A soma recebe inválido e também fica quieta.

4 · Desenhe as duas árvores anotadas da soma dos dígitos para 507. Que valores aparecem?
Uma resposta

Só sintetizado: o N mais fundo vale 5, o do meio 5 + 0 = 5, o de cima 5 + 7 = 12. Com herdado: X.h = 5, X₁.h = 5 + 0 = 5, X₂.h = 5 + 7 = 12; no ε, X₂.s = 12, e 12 sobe até N.v.

5 · Quanto vale este programa? 
let a = 1 in
  let a = a + 1, b = a + a in a + b
Uma resposta

6. No let interno, o primeiro a usa o de fora: a = 2. A lista é sequencial, então b = a + a já usa o novo a: b = 4. a + b = 2 + 4.

6 · O que este trecho em C imprime? 
int a = 1;
{ int a = 2;
  { a = a + 1; print(a); }
  print(a); }
print(a);
Uma resposta

3, 3 e 1. O bloco mais interno não declara a: a = a + 1 acha o a = 2 do bloco do meio e muda ele para 3. O print do meio vê o mesmo 3. Fora, o a global nunca mudou.

7 · Escreva o termo2 da calculadora com divisão inteira (DIV). Que cuidado vale também para a divisão?
Uma resposta

Acrescente if self.tokenCorrente.tipo == 'DIV': self.comparar('DIV'); return self.termo2(herdado // self.fator()). O mesmo da subtração: o herdado vem antes. 12 / 3 / 2 tem de dar (12 // 3) // 2 = 2, e não 12 // (3 // 2) = 12.

8 · Com f(int a, int b), numa linguagem que converte int para real e nunca o contrário, quais chamadas passam: f(1, 2), f(1), f(1.0, 2), f(1, 2, 3)?
Uma resposta

Só f(1, 2). f(1) e f(1, 2, 3) erram o número; f(1.0, 2) passaria um real para int, que perde informação e não é conversão permitida.
